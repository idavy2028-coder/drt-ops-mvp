# P6-2 真实终端资料收集指南

## 使用边界

仓库中的 CSV 仅是字段模板，必须保持四行占位记录。不得填写真实手机号、终端 ID、VIN、鉴权码、个人姓名、真实 IP、媒体凭证或可反推出上述信息的内容。填好的资料保存到 Git 忽略路径，例如 `.private/p6-2-real-terminals.csv`，并按最小权限共享；报告、截图和日志只引用 `TERM-ALPHA` 等终端别名及脱敏车牌别名。

## 录入格式与必填规则

- 文件编码为 UTF-8，首行为固定表头；每行代表一台终端，必须恰好四行，别名只能使用 `TERM-ALPHA`、`TERM-BRAVO`、`TERM-CHARLIE`、`TERM-DELTA` 这类非身份化别名。
- `bound_plate_alias` 使用 `PLATE-ALPHA` 等脱敏别名；`private_terminal_file_ref` 只写私有文件相对引用，不写文件内容、凭证或云盘公网地址。
- 手机号、终端 ID 等敏感字段在仓库模板中保持 `PRIVATE_VALUE`；私有文件中也应使用受控引用或加密存储。制造商、型号、固件、JT/T 808 版本、源坐标系、T/JSATL12 标准、ADAS、DMS、JT/T 1078 能力、两类上报频率、验收时间窗、现场联系人角色和确认状态均为必填。
- 频率使用明确单位（例如 `秒/次` 或 `分钟/次`），坐标系写标准名称及版本；能力字段使用 `支持/不支持/待确认`，不得用含糊的“有/无”。
- `network_reachability`、`nat_firewall_check`、`vendor_security_alarm_test`、`vendor_static_replay_method`、`attachment_control_capability` 必须记录结论和证据引用；结论为 `待确认` 时不得标记资料已确认。
- `external_media_test_profile_ref` 只引用私有 profile 文件名或内部编号；`onsite_contact_role` 只填角色（如“车队管理员”“厂商技术支持”），不填姓名、手机号或邮箱。

## 录入前核对清单

1. 四台终端均已由现场确认，别名与脱敏车牌一一对应且无重复。
2. 私有资料文件位于 `.private/` 或等效忽略路径，权限为最小可读；未进入 Git 暂存区。
   执行 `git check-ignore --no-index .private/p6-2-real-terminals.csv .env .env.production.local`，三条路径都必须被命中；再执行 `git check-ignore --no-index .env.example`，该模板不得被忽略。
   最后执行 `git status --short --untracked-files=all`，确认没有 `.env`、`.private/` 或真实终端资料进入工作树清单。
3. 已确认协议版本、坐标系、T/JSATL12、JT/T 1078 能力及固件版本，并留存来源引用。
4. 已完成网络可达、NAT/防火墙、厂商安全报警与静态回放核对；失败项写明原因、时间窗和补证计划。
5. 已确认附件控制方式和外部媒体测试 profile；媒体文件或 token 仅留在受控私有位置。

## 网络、厂商回放与附件能力清单

| 类别 | 必须确认 | 最低证据 | 不得放入 Git 的内容 |
| --- | --- | --- | --- |
| 网络 | 网关可达性、传输方向、端口/协议、NAT 类型、防火墙放行结果 | 脱敏连通性记录、检查时间、结果码 | 真实 IP、端口密码、鉴权码 |
| 厂商安全报警 | 报警触发条件、终端上报、网关接收、告警清理 | 厂商测试单或脱敏事件流水号 | 真实终端 ID、个人信息 |
| 静态回放 | 回放文件/脚本私有引用、时间窗、消息类型、预期结果 | 私有回放 profile 引用和结果摘要 | 公网媒体 URL、访问 token |
| 附件 | 是否支持下发/查询/停止、权限边界、失败重试 | 能力矩阵、控制结果和审计引用 | 媒体凭证、原始照片/视频 |

## ADAS/DMS 覆盖与验收矩阵

四台终端都必须在私有资料中明确 ADAS、DMS 状态；至少一台须具备并验证附件控制能力。下表是报告中的覆盖矩阵，使用别名和 `支持/不支持/待确认`，不填真实身份：

| 终端别名 | ADAS 状态/证据 | DMS 状态/证据 | 安全报警回放 | 附件控制 | 验收结论 |
| --- | --- | --- | --- | --- | --- |
| TERM-ALPHA | 必填 | 必填 | 必填 | 必填 | 通过/有条件通过/不通过 |
| TERM-BRAVO | 必填 | 必填 | 必填 | 必填 | 通过/有条件通过/不通过 |
| TERM-CHARLIE | 必填 | 必填 | 必填 | 必填 | 通过/有条件通过/不通过 |
| TERM-DELTA | 必填 | 必填 | 必填 | 必填 | 通过/有条件通过/不通过 |

验收“通过”要求四台资料完整、网络和协议证据可追溯、厂商回放结果闭环，且至少一台附件控制成功并有审计证据；任一待确认项只能给“有条件通过”，关键能力缺失或证据不可追溯则为“不通过”。

## 脱敏报告规则

- 报告、截图文件名、日志摘录和缺陷单只使用终端别名、车牌别名、时间窗和内部证据编号。
- 手机号、终端 ID、VIN、鉴权码、真实 IP、姓名、邮箱、媒体 URL/token 一律删除或以不可逆占位符替换；不要用部分掩码保留可关联片段。
- 报告必须说明资料来源类型、采集时间窗、证据引用、已验证能力、未闭环项及责任角色；不以“字段已填写”替代“测试已通过”。
- 提交前检查 Git 跟踪列表、CSV 内容、Markdown 表格、附件文件名和命令输出，确认不存在敏感模式；发现疑似真实值时立即移除并重新扫描。
