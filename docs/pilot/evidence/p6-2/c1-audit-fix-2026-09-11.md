# C1 审计修复验证（2026-09-11）

结论：本地审计缺口已修复，相关测试通过；未部署，不代表A阶段就绪。

## 修复合同

- JtTerminalSessionLeaseService成功续租记录SESSION_LEASE_RENEWED；第一次有效释放记录SESSION_LEASE_RELEASED。leaseGeneration不随普通续租变化，version由JPA递增。
- 元数据记录connectionId、gateway实例摘要、leaseGeneration、行version、前后有效期、最近消息时间及释放时间；实体ID为terminalId。审计不存令牌、密码或原始报文，实例名用固定长度摘要避免长度/转义膨胀。
- 重复释放ALREADY_RELEASED、失效所有者STALE_OWNER_IGNORED、被拒续租不新增成功状态审计。未另设计失败请求审计。
- 原ADAS/DMS入库只有报警与outbox，没有独立业务审计。JpaAlarmStore在实际ALARM_CREATED/ALARM_ENDED分支写VEHICLE_ALARM_CREATED/VEHICLE_ALARM_ENDED；实体为alarm ID，元数据关联terminalId、onboardSystemId、vehicleId、locationEventId、模块、类型与发生/结束时间。
- GatewayStateAudit要求MANDATORY现有事务。租约审计与租约保存同事务；报警审计、alarm/outbox及幂等receipt同事务。审计失败不吞异常，不保留无审计的成功业务状态。重放不走实际变更分支，不重复写成功审计。
- 使用现有audit_logs，jt_gateway_audit_events没有重复写一份同类审计。后者增量0是当前明确合同，不再作为审计缺失判据；审计验收检查audit_logs指定action。

测试驱动：先新增断言，实际复现租约应有1条但为0、双报警应有2条但为0（.tmp/c1-audit-red.log）；再实施修复。首轮测试新增Mockito引用编译失败，改用项目既有Java代理方式，不新增依赖。随后101项中100通过，1个回滚断言因Spring将IllegalStateException转换为InvalidDataAccessApiUsageException而失败；明确检查包装类型及根因后，Gps完整67/67通过（.tmp/c1-audit-rollback-r3.log）。不修改产品行为去适配测试。

真实HTTP/TCP场景：0x0200双START报警2条，定位WARNING、snapshotApplied=true；renew HTTP200、expires_at延长、version+1、审计增量1；release HTTP200/RELEASED、released_at/原因正确、version再+1、累计审计增量2；再次release为ALREADY_RELEASED且审计仍1条释放；释放后renew HTTP409。

回滚/幂等：注入审计写入失败，续租有效期和version不变、释放时间仍空；报警创建、outbox和receipt均回滚；恢复后同key成功，再同key/不同key同事实均重放；合法END一次审计，重复END不追加。现有租约并发、token轮换与所有权隔离测试通过。

覆盖限制：报警END审计失败未单独注入回滚测试；报警字段关联由实现及双报警归属验证支持，未逐字段断言审计JSON。审计字段单元主要覆盖租约续租、安全长度和无凭据。测试不是PostgreSQL V21或正式JAR复验。
