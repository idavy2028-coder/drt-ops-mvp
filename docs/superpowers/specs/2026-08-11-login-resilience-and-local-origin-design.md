# 登录韧性与本地来源配置设计

## 1. 背景

2026-08-11 在真实 `admin` 登录验证中连续出现“用户名或密码不正确”，但同一凭据通过真实 API 和前端代理直接调用能够登录。最终确认存在两类独立问题：

1. 登录页把认证失败、CORS 拒绝、网络异常和登录后的路由异常统一显示为“用户名或密码不正确”，导致排障方向错误。
2. Chrome 密码管理器在提交时恢复了已保存的旧密码，页面没有提示用户检查自动填充状态。
3. 临时前端地址使用 `5176` 端口，但真实 API 的 CORS 白名单仅允许 `http://127.0.0.1:5174`，浏览器携带 `Origin` 后收到 HTTP 403；不携带浏览器 `Origin` 的命令行请求则正常，形成误导性的对照结果。

本设计将这些问题沉淀为可测试、可诊断且不降低安全边界的登录流程。

## 2. 目标

- 登录失败时准确区分凭据、来源地址、网络和页面跳转问题。
- 密码重置后，降低浏览器保存的旧密码被重复提交的概率。
- 临时密码账号登录成功后稳定进入强制改密页。
- 将本地常用前端来源显式写入配置，避免依赖手工创建容器时临时补值。
- 保持密码管理器兼容、刷新令牌安全属性和精确 CORS 白名单。
- 为运维人员提供不包含密码、令牌和用户隐私的排障证据。

## 3. 非目标

- 不禁用浏览器密码管理器。
- 不读取、记录或回显用户密码及原始令牌。
- 不允许 `*` 通配 CORS 来源，也不使用宽泛来源模式替代精确列表。
- 不改变 BCrypt、JWT、刷新令牌轮换、账号锁定或角色权限模型。
- 不接入 LDAP、OIDC 或其他新的身份提供方。

## 4. 方案决策

采用“前端错误分类 + 凭据重试引导 + 显式本地 CORS 配置”组合方案。

未采用以下方案：

- 仅修改提示文案：无法阻止环境继续遗漏来源配置。
- 禁用密码管理器：会降低正常用户体验，并破坏浏览器安全工具的标准语义。
- CORS 使用通配符：与携带 Cookie 的请求不兼容，也扩大了本地管理 API 的暴露面。
- 将所有临时端口自动放行：端口范围不可审计，且难以区分预期环境与误配置。

## 5. 前端登录流程

登录提交拆分为两个明确阶段：

1. **认证阶段**：调用 `/api/auth/login`，根据响应或异常生成登录失败类型。
2. **导航阶段**：认证成功后，根据 `mustChangePassword` 决定进入改密页或原目标页面；导航异常不得回退为凭据错误。

### 5.1 认证失败分类

| 条件 | 稳定代码 | 页面行为 |
| --- | --- | --- |
| HTTP 401 | `LOGIN-401` | 显示“用户名或密码不正确”；清空密码；聚焦密码框；提示检查浏览器保存的旧密码 |
| HTTP 403 | `LOGIN-ORIGIN-403` | 显示“当前访问地址未被运营服务允许”；提示核对本地前端地址和 CORS 白名单 |
| `TypeError` 等连接失败 | `LOGIN-NETWORK` | 显示“暂时无法连接运营服务，请检查服务与网络” |
| 其他认证异常 | `LOGIN-UNKNOWN` | 显示通用登录失败提示，不猜测为密码问题 |
| 登录成功后路由失败 | `LOGIN-NAVIGATION` | 显示“登录成功，但页面跳转失败”；保留已建立的内存会话，允许用户重试跳转或刷新 |

错误代码可显示在页面提示中，便于截图和日志关联；不得附带用户名、密码、访问令牌、刷新令牌或完整响应体。

### 5.2 浏览器密码管理器兼容

- 用户名输入框继续使用 `autocomplete="username"`。
- 密码输入框继续使用 `autocomplete="current-password"`。
- 不通过脚本检测、读取或修改浏览器保存的密码。
- 仅在 HTTP 401 后清空当前密码框并聚焦，避免旧值被连续重提。
- 登录页常驻一条简短说明：密码刚被管理员重置时，应重新输入并更新浏览器保存的密码。
- 不在 HTTP 403、网络错误或导航错误时清空密码，以免把环境问题伪装成凭据问题。

### 5.3 首次登录改密

- 登录响应中 `mustChangePassword=true` 时，登录页直接导航到命名路由 `changePassword`。
- 路由守卫继续作为第二道保护，阻止临时密码账号访问业务页面。
- 改密成功后沿用现有行为：撤销旧会话、返回登录页，用户使用新密码重新登录。

## 6. CORS 配置

### 6.1 精确来源列表

本地与试点 Docker 配置显式提供 `DRT_WEB_ALLOWED_ORIGINS`。默认本地列表覆盖：

- `http://localhost:5173`
- `http://127.0.0.1:5173`
- `http://localhost:5174`
- `http://127.0.0.1:5174`
- `http://localhost:5176`
- `http://127.0.0.1:5176`

这些地址仅用于本地开发、试点验证和 PR 预览。非本地部署必须通过环境变量显式覆盖为实际管理端来源。

### 6.2 安全约束

- 配置解析继续去除首尾空白和空项。
- 任一来源为 `*` 时启动失败。
- `allowCredentials(true)` 保持不变。
- 仅 `/api/**` 应用该 CORS 配置。
- 不根据请求动态回显未知来源，不接受正则或端口范围。

### 6.3 运维可诊断性

- Docker Compose 明确声明 `DRT_WEB_ALLOWED_ORIGINS`，避免环境变量只存在于手工启动命令中。
- 排障文档提供浏览器与命令行结果不一致时的检查顺序：浏览器 Origin、实际 API 数据源、前端代理目标、密码管理器旧值。
- 文档和日志不得记录真实密码、密码哈希、Cookie 或令牌。

## 7. 组件与文件范围

### 7.1 前端

- `apps/admin-web/src/pages/LoginPage.vue`
  - 分离认证和导航错误处理。
  - 增加稳定错误代码、旧密码提示、401 清空与聚焦。
  - `mustChangePassword=true` 时直接进入改密页。
- `apps/admin-web/src/pages/login-page.test.ts`
  - 覆盖各错误分类、密码框处理和改密跳转。
- `apps/admin-web/src/api/errors.ts`
  - 仅在通用错误模型确有复用价值时扩展；登录专用文案不污染其他业务页面。

### 7.2 API 与运行配置

- `apps/api/src/main/java/com/idavy/drtops/config/WebCorsConfiguration.java`
  - 保留精确来源和通配符拒绝约束；必要时提取可测试的来源解析边界。
- `apps/api/src/main/resources/application.yml`
  - 提供与本地开发一致的安全默认值或明确环境变量入口。
- `infra/docker-compose.pilot.yml`
  - 显式注入本地试点来源列表，并允许部署环境覆盖。
- 新增或扩展 CORS 配置测试
  - 验证允许来源、未知来源和通配符启动失败。

### 7.3 文档

- 新增本地管理员登录排障说明。
- `progress.md` 记录问题根因、修复边界和验证结论。

## 8. 测试设计

### 8.1 前端单元测试

- 401 显示 `LOGIN-401`，清空密码并将焦点返回密码框。
- 401 提示检查浏览器保存的旧密码。
- 403 显示 `LOGIN-ORIGIN-403`，不显示“用户名或密码不正确”，不清空密码。
- 网络异常显示 `LOGIN-NETWORK`。
- 未知异常显示 `LOGIN-UNKNOWN`。
- 登录成功且必须改密时直接进入 `changePassword`。
- 登录成功但导航失败时显示 `LOGIN-NAVIGATION`，不显示凭据错误。

### 8.2 API 测试

- 已配置的 `127.0.0.1:5174` 和 `localhost:5176` 预检请求获得对应 `Access-Control-Allow-Origin`。
- 未配置来源不获得放行响应。
- `*` 配置导致应用配置创建失败。
- Cookie 凭据支持和允许方法集合保持不变。

### 8.3 验证命令

- 管理端目标 Vitest。
- 管理端完整 Vitest、类型检查和构建。
- API CORS 定向测试；风险允许时执行 API 完整测试。
- `git diff --check` 和敏感信息扫描。

### 8.4 真实浏览器验收

1. 使用允许的本地来源连接真实 API。
2. 使用测试账号验证错误密码时清空并聚焦。
3. 使用强制改密测试账号验证直接进入改密页。
4. 使用未允许来源验证页面显示来源配置错误而非密码错误。
5. 验收过程不读取或输出浏览器密码库、密码、Cookie 或令牌。

## 9. 完成标准

- 同一登录失败不再同时可能被解释为密码、CORS、网络或导航问题。
- Chrome 保存旧密码时，用户在一次失败后获得明确、可执行的修正提示。
- 5173、5174、5176 的本地标准地址与真实 API 配置一致。
- 临时密码账号稳定进入改密页，正常账号按权限进入目标页面。
- 自动化测试、构建、差异检查和敏感信息扫描通过。
- 文档不包含任何真实凭据或令牌。

## 10. 回滚

- 前端行为可通过单独回退登录页与测试提交恢复。
- CORS 配置可通过 `DRT_WEB_ALLOWED_ORIGINS` 覆盖为部署前值，无需修改数据库。
- 若新版前端本地服务异常，可重新启动原 `drt-ops-pilot-web` 容器；该操作不影响 API 和业务数据。
