# P6-2 车载系统聚合、多设备角色与位置主备设计

日期：2026-08-29（Asia/Shanghai）

状态：设计章节已确认，正式规格待人工复核

关联规格：

- `docs/superpowers/specs/2026-08-12-p6-2-jt808-active-safety-gateway-design.md`
- `docs/superpowers/specs/2026-08-29-p6-2-terminal-identity-isolation-cross-connection-auth-design.md`

## 1. 文档目的与覆盖关系

### 1.1 目的

实际公交车辆可能同时安装两台物理设备：

- 调度终端负责调度业务；
- 行车记录仪负责视频、DSM、ADAS 等主动安全业务；
- 两台设备分别使用独立终端身份并建立独立 JT808 TCP 连接；
- SIM 卡可安装在任一设备，另一台设备通过本地网络共享公网连接；
- 也存在只安装行车记录仪或只安装调度终端的车辆。

本规格将 P6-2 从“一辆车对应一台终端”调整为“一辆车对应一个逻辑车载系统，车载系统包含一个或多个物理设备节点”。后台可以按一套车载终端系统聚合展示，但协议身份、凭证、会话、故障和审计必须保持设备级隔离。

### 1.2 对上一份身份隔离规格的覆盖

本规格覆盖 `2026-08-29-p6-2-terminal-identity-isolation-cross-connection-auth-design.md` 中以下假设：

- “每辆车至多绑定一台活动终端”；
- “不同终端不得共享车辆标识”；
- “车辆标识不一致一律视为设备身份碰撞”；
- “一个车辆绑定只返回一套设备角色和能力”。

以下决策继续有效：

- 每台物理设备的终端手机号语义身份和终端 ID 全局唯一；
- 每台物理设备使用独立鉴权码、令牌版本和 TCP 会话；
- 按协议身份执行跨连接鉴权；
- 来源 IP、TCP 端口和 SIM 所在设备不作为身份依据；
- 原始身份、鉴权码和摘要不得进入公开日志或报告；
- 测试设备必须以精确设备身份进行维护隔离。

如两份规格存在冲突，以本规格为准。

## 2. 已确认事实与决策

### 2.1 已确认事实

1. 双设备车辆上的调度终端和行车记录仪使用独立、唯一的 `terminal_id`。
2. 两台设备分别建立独立 JT808 TCP 连接。
3. 两台设备通常在 `0x0100` 中上报同一个真实车牌作为 `vehicle_identifier`。
4. 后台车辆档案的车牌由管理员维护，设备通过预置关系绑定到同一车辆。
5. `vehicle_identifier` 是车辆身份辅助字段，不作为物理设备唯一主键。
6. 双设备车辆以调度终端作为位置主源，行车记录仪作为备源。
7. 单设备车辆按已验证能力工作，不按设备名称强行分配业务能力。

### 2.2 已确认架构决策

- 采用“车载系统聚合 + 物理设备节点 + 能力角色”模型。
- 设备能力与运营角色分离：能力是设备事实，角色是管理员对某辆车的受控分配。
- SIM 所在设备只承担 `WAN_UPLINK` 网络角色，不自动获得调度、位置或安全业务权限。
- 同车多设备可以共享车牌；终端手机号语义身份和终端 ID 不得共享。
- 两台设备的原始位置均可保存，但同一时刻只有一个权威来源更新车辆位置快照。
- 当前仅启动的测试行车记录仪不具备已验证调度能力，车辆保持不可调度。

## 3. 目标、成功标准与非目标

### 3.1 目标

1. 支持同车双设备、仅行车记录仪、仅调度终端三类安装形态。
2. 支持 SIM 在任一设备上的两种双设备网络拓扑。
3. 后台按车辆聚合展示，又能下钻到物理设备的身份、会话、协议、能力和故障。
4. 防止两路位置互相覆盖，并提供可审计的主备切换。
5. 根据已验证能力决定车辆是否可以调度以及可用的安全、视频能力。
6. 允许同车设备共享 `vehicle_identifier`，同时阻止跨车辆误绑和设备身份重复。
7. 通过扩展式数据库迁移保留现有终端 UUID、鉴权材料、时间戳和审计历史。

### 3.2 成功标准

- 一辆车拥有一个活动 `OnboardSystem`。
- 一个 `OnboardSystem` 可包含一个或多个活动物理设备。
- 双设备可以同时注册、鉴权和保持会话，不互相接管或断开。
- 同车共享车牌不会触发身份碰撞。
- 两台设备同时上报位置时，只有当前权威来源更新车辆快照。
- 主源失效后按规则切到备源，主源恢复并连续三条有效位置后切回。
- 无 `DISPATCH` 角色的车辆不进入自动调度车池。
- 设备发送超出角色的数据不会产生业务事实。
- 管理端能区分 `NOT_INSTALLED`、`READY`、`DEGRADED` 和 `UNAVAILABLE`。
- 迁移及完整回归通过，测试总数不低于当前 701 项基线。

### 3.3 非目标

- 本规格不实现完整 GB/T 28787-2023 的 `0x0Bxx/0x8Bxx` 公交业务消息。
- 本规格不启用真实媒体服务或附件二进制链路。
- 不把共享公网 IP、NAT 映射或 SIM 号码作为设备身份。
- 不允许一条 TCP 连接代理或混装另一台物理设备的 JT808 身份。
- 不根据设备名称、型号或消息长度自动推断业务角色。
- 不删除重建现有终端，不直接操作生产数据库修正绑定。

## 4. 方案比较与裁决

| 方案 | 优点 | 风险 | 裁决 |
| --- | --- | --- | --- |
| 车载系统聚合 + 物理设备节点 + 能力角色 | 支持多设备、单设备、SIM 迁移和未来扩展；身份和审计清晰 | 需要新增聚合、成员、角色和主备模型 | **采用** |
| 多终端直接绑定车辆并增加固定设备类型 | 改动较少 | 设备类型与能力耦合，难以支持组合设备或第三类设备 | 不采用 |
| 一个终端记录保存多套身份和会话 | 后台对象少 | 鉴权、在线状态、故障和数据来源互相污染 | 禁止 |

## 5. 领域模型

### 5.1 `OnboardSystem`

`OnboardSystem` 是车辆上的逻辑车载系统聚合根：

- `id`
- `vehicleId`
- `status`
- `operatingMode`
- `activeLocationDeviceId`
- `version`
- 创建、更新时间和操作人

一辆车同一时刻至多一个活动 `OnboardSystem`。车牌仍只在 `vehicles` 表中全局唯一。

`status` 取值为 `ACTIVE/SUSPENDED/RETIRED`。`operatingMode` 取值为：

- `DISPATCH_SERVICE`：该车辆计划进入调度运营，`DISPATCH` 和可用位置是必需能力；
- `SAFETY_MONITOR_ONLY`：只进行定位、视频或主动安全监控，不要求调度能力，车辆必须不可调度。

### 5.2 物理设备节点

现有 `jt_terminals` 继续表示物理设备，不新建第二套终端身份表。每台设备保留：

- 终端手机号及 V18 规范身份；
- 终端 ID；
- 制造商、型号和固件；
- 独立鉴权摘要、令牌版本和注册/鉴权时间；
- 独立会话和在线状态；
- 协议档案、能力事实和设备级审计。

### 5.3 成员关系

新增 `onboard_device_memberships`：

- `onboardSystemId`
- `terminalId`
- `status=ACTIVE/REMOVED`
- `validFrom/validTo`
- 加入、移除原因及操作人
- `version`

一台物理设备同一时刻只能属于一个活动车载系统。成员历史只追加，不覆盖。

### 5.4 能力事实

新增设备能力事实，至少包括：

- `JT808_LOCATION`
- `GBT28787_DISPATCH`
- `VENDOR_DISPATCH`
- `ADAS`
- `DMS`
- `VIDEO`
- `JT1078_MEDIA`

能力状态为 `DECLARED`、`VERIFIED` 或 `DISABLED`。只有 `VERIFIED` 能力可以被分配运营角色。验证记录保存脱敏证据引用、验证时间和验证人。

### 5.5 角色历史

新增 `onboard_device_role_assignments`，角色包括：

- `DISPATCH`
- `LOCATION_PRIMARY`
- `LOCATION_BACKUP`
- `ACTIVE_SAFETY`
- `VIDEO`
- `WAN_UPLINK`

同一车载系统内：

- `DISPATCH` 至多一个活动设备；
- `LOCATION_PRIMARY` 至多一个活动设备；
- `LOCATION_BACKUP` 至多一个，且不得与主设备相同；
- `ACTIVE_SAFETY` 至多一个活动主设备；
- `VIDEO` 至多一个活动主设备；
- `WAN_UPLINK` 至多一个活动设备。

一个设备可以承担多个角色，但每个角色必须有对应已验证能力。角色变更使用 `expectedVersion`、原因和追加式历史。

## 6. 协议档案

每台设备分别登记：

```text
transportProfile   JT808_2019 | JT808_2013
businessProfile    GBT28787_2023 | VENDOR_DISPATCH | NONE
safetyProfile      GBT28787_2023 | JSATL12_2017 | NONE
mediaProfile       JT1078_2016 | NONE
```

协议档案是解码器选择依据，不得通过型号、消息长度或载荷内容猜测。

典型配置：

- 调度终端：`JT808_2019 + GBT28787_2023` 或已验证厂商调度档案；
- 行车记录仪：`JT808_2019 + GBT28787_2023` 主动安全子能力，或 `JSATL12_2017 + JT1078_2016`；
- 不支持调度业务的行车记录仪：`businessProfile=NONE`。

“新国标行车记录仪”是设备名称，不等同于完整 GB/T 28787-2023 兼容声明。每类消息仍需样本和测试证明。

## 7. 注册与身份校验

### 7.1 设备定位

注册时先使用 `terminal_phone` 规范身份和 `terminal_id` 唯一定位物理设备，再读取其车载系统成员关系和角色。`vehicle_identifier` 不参与物理设备唯一查找。

### 7.2 硬门禁

以下条件失败时拒绝注册：

- 终端手机号语义身份不存在或重复；
- 终端 ID 不存在、重复或与手机号命中不同设备；
- 设备状态不允许注册；
- 传输协议版本不匹配；
- 设备没有活动车载系统成员关系；
- 成员关系指向不可用车辆；
- `vehicle_identifier` 命中另一辆已存在车辆；
- 设备身份试图跨车辆聚合复用。

### 7.3 车辆标识辅助校验

- 与绑定车辆车牌一致：`APPROVED`；
- 同车多设备上报同一车牌：`APPROVED`；
- 与后台车牌不一致，但不对应其他车辆：`APPROVED_WITH_WARNING`，记录 `VEHICLE_IDENTIFIER_MISMATCH`；
- 命中另一辆车辆：拒绝并记录 `VEHICLE_IDENTIFIER_CONFLICT`。

设备侧成功结果仍使用正常 `0x8100`。警告仅进入内部响应、审计和后台状态，不通过协议暴露平台数据。

不得用 `vehicle_identifier` 自动创建车辆、移动设备或改变角色。

### 7.4 跨连接鉴权

跨连接鉴权继续按物理设备协议身份执行。成功响应增加：

- `terminalId`
- `onboardSystemId`
- `vehicleId`
- 当前角色集合
- 坐标系和能力快照
- 令牌版本

同连接与跨连接鉴权必须复用同一核心服务。`last_authenticated_at` 只在物理设备鉴权成功时更新。

## 8. 会话与连接管理

### 8.1 会话键

活跃会话以物理 `terminalId` 为键，不以 `vehicleId`、车牌、公网 IP 或 `OnboardSystem` 为键。

同一设备新连接鉴权成功后只接管该设备旧连接。同车另一设备的连接不受影响。

### 8.2 SIM 与网络共享

`WAN_UPLINK` 只记录当前公网出口所在设备：

- `DIRECT_CELLULAR`：设备直接使用自身蜂窝网络；
- `SHARED_LAN_CLIENT`：设备通过另一设备或车载路由共享公网。

两种模式下，每台设备都必须使用自己的协议身份、鉴权码和 TCP 连接。SIM 迁移只改变 `WAN_UPLINK` 和网络资料，不迁移身份、凭证、会话或业务角色。

### 8.3 设备状态

设备状态分别记录：

- TCP 连接；
- JT808 鉴权；
- 公交业务登记；
- 最近有效位置；
- 最近主动安全事实；
- 媒体能力；
- 最近故障。

不得把一个设备在线推导为同车所有设备在线。

## 9. 位置主备与质量仲裁

### 9.1 原始事件

两台设备的合法位置均写入不可变位置事件，并附带：

```text
terminalId + onboardSystemId + vehicleId + sourceRole
```

原始事件互不覆盖。车辆快照只由当前权威位置源更新。

### 9.2 主源优先

双设备车辆默认：

- 调度终端：`LOCATION_PRIMARY`；
- 行车记录仪：`LOCATION_BACKUP`。

主源位置为 `GOOD` 或 `WARNING` 且未过期时，备源只能保存原始事件，不能更新车辆快照。

### 9.3 失效阈值

主源失效阈值为：

```text
max(30 秒, 2 × 该设备预期上报间隔)
```

以下任一条件触发备源接管：

- 主源超过失效阈值没有有效位置；
- 主源位置质量为 `QUARANTINED` 或 `REJECTED`；
- 主源会话离线且备源有新鲜有效位置。

备源自身必须为 `GOOD/WARNING` 且未过期。

### 9.4 恢复与防抖

主源恢复后必须连续产生 3 条有效、时间单调递增的位置，才重新成为权威来源。每次切换记录 `LOCATION_SOURCE_SWITCHED`，包含设备安全别名、前后角色、原因和时间。

迟到事件和终端时间倒退事件可以保留为审计事实，但不得覆盖较新的车辆快照。

### 9.5 单设备车辆

- 仅行车记录仪且具备定位能力：自动作为 `LOCATION_PRIMARY`；
- 仅调度终端且具备定位能力：自动作为 `LOCATION_PRIMARY`；
- 无已验证定位能力：位置为 `UNAVAILABLE`。

## 10. 能力驱动的运营规则

### 10.1 调度准入

车辆进入自动调度车池必须同时满足：

- 车辆自身 `dispatchable=true`；
- 车载系统存在活动 `DISPATCH` 角色；
- 角色设备具有已验证调度能力；
- 设备已鉴权并完成所需业务登记；
- 当前权威位置可用。

只有行车记录仪但未验证调度能力的车辆保持不可调度，即使其定位、ADAS、DMS 和视频正常。

### 10.2 角色数据归属

- 调度消息只接受 `DISPATCH` 设备；
- ADAS/DMS 事实只接受 `ACTIVE_SAFETY` 设备；
- 视频和媒体控制只接受 `VIDEO` 设备；
- 位置只接受 `LOCATION_PRIMARY/BACKUP` 设备；
- `WAN_UPLINK` 不授予任何业务消息权限。

超出角色的消息不写入业务事实，记录 `DEVICE_ROLE_VIOLATION`。

### 10.3 能力缺失与故障

`NOT_INSTALLED` 表示该车辆没有配置该能力，不等同于已安装设备故障。已安装角色不可用时使用 `UNAVAILABLE` 或 `DEGRADED`。

车辆是否为整体 `OPERATIONAL`，取决于其运营模式要求的角色，而不是要求所有可能能力都已安装。

## 11. 安装场景矩阵

| 场景 | 调度终端 | 行车记录仪 | 权威位置 | 调度准入 |
| --- | --- | --- | --- | --- |
| 双设备，SIM 在调度终端 | `DISPATCH/LOCATION_PRIMARY/WAN_UPLINK` | `LOCATION_BACKUP/ACTIVE_SAFETY/VIDEO` | 调度终端 | 正常 |
| 双设备，SIM 在行车记录仪 | `DISPATCH/LOCATION_PRIMARY` | `LOCATION_BACKUP/ACTIVE_SAFETY/VIDEO/WAN_UPLINK` | 调度终端 | 正常 |
| 仅行车记录仪 | 不安装 | `LOCATION_PRIMARY/ACTIVE_SAFETY/VIDEO/WAN_UPLINK` | 行车记录仪 | 默认禁止；验证调度能力后可调整 |
| 仅调度终端 | `DISPATCH/LOCATION_PRIMARY/WAN_UPLINK` | 不安装 | 调度终端 | 正常；安全和视频为 `NOT_INSTALLED` |

当前仅启动的测试行车记录仪属于第三种场景。它绑定独立测试车载系统，车辆不可调度，不授予 `DISPATCH`。

如果某测试记录仪与生产车辆上已安装记录仪竞争同一个 `ACTIVE_SAFETY` 或 `VIDEO` 角色，则仍必须隔离到测试车辆，不允许作为生产车辆的第二个同角色主设备。

## 12. 数据库迁移

### 12.1 V19 扩展阶段

新增迁移 `V19__add_composite_onboard_system_model.sql`，只增加结构和兼容数据，不删除旧约束。

新增：

- `onboard_systems`
- `onboard_device_memberships`
- `onboard_device_capabilities`
- `onboard_device_protocol_profiles`
- `onboard_device_role_assignments`
- 角色和位置源切换审计字段

现有 `jt_terminals`、终端 UUID、鉴权材料、注册/鉴权时间和审计表不变。

### 12.2 迁移阶段

1. 为每个现有活动车辆绑定创建一个 `OnboardSystem`。
2. 将现有终端回填为该系统的成员。
3. 使用经过人工确认的私密 migration manifest 分配能力、协议档案和角色。
4. 禁止按型号或当前在线情况推断角色。
5. 执行只读 dry-run，输出安全别名、对象 UUID、差异字段和版本，不输出真实身份。
6. 使用 API 和 `expectedVersion` 应用角色及协议档案。
7. 核对成员、角色、位置源和调度准入。

### 12.3 V20 收口阶段

新增迁移 `V20__replace_single_terminal_vehicle_binding_constraint.sql`。该迁移只在 V19 数据回填、角色分配和兼容验证完成后执行。

只有当所有活动终端都有唯一活动成员关系且关键角色约束满足后，才取消旧的“一辆车一个活动终端绑定”唯一索引。

新约束包括：

- 活动车载系统的 `vehicleId` 唯一；
- 活动成员的 `terminalId` 唯一；
- 同系统排他角色唯一；
- 位置主、备设备不同；
- 设备角色必须对应已验证能力。

旧绑定历史不得删除。收口后旧代码禁止写入旧绑定模型，可保留只读兼容视图。

### 12.4 回滚

- 扩展阶段可回滚代码而不删除新表；
- 角色迁移阶段失败时保持旧绑定仍为权威，不自动清除已写历史；
- 解除旧唯一索引后，不得直接回滚到不理解多设备的旧 API/gateway；
- 任一回滚不得把两个设备合并回同一终端身份。

## 13. 后台管理设计

### 13.1 聚合卡片

车辆详情显示一张“车载终端系统”卡片：

- 整体状态；
- 当前权威位置来源；
- 当前 WAN 出口设备；
- 调度、定位、主动安全、视频四个维度；
- 已安装设备数量。

### 13.2 设备明细

展开后分别显示：

- 安全别名和设备类型；
- 已验证能力和活动角色；
- 四类协议档案；
- 连接、鉴权和业务登记状态；
- 最近注册、鉴权、位置、报警和故障时间；
- `DIRECT_CELLULAR` 或 `SHARED_LAN_CLIENT` 网络模式。

敏感身份只显示脱敏值。

### 13.3 操作边界

设备级操作：身份纠正、认证轮换、暂停、恢复、断开、能力验证、协议档案、固件和故障。

车载系统级操作：成员管理、角色分配、位置主备、WAN 出口和运营模式。

所有变更要求 `expectedVersion`、原因、权限和审计。不得因某设备在线而把同车另一设备显示为在线。

### 13.4 聚合状态

维度状态为 `READY/DEGRADED/UNAVAILABLE/NOT_INSTALLED`。整体状态为：

- `OPERATIONAL`：运营模式要求的角色全部可用；
- `DEGRADED`：车辆仍可运行，但已安装或必需角色异常；
- `OFFLINE`：没有可用通信设备。

## 14. 异常处理与审计

| 条件 | 处理 |
| --- | --- |
| 第二个排他角色 | HTTP 409，不覆盖原角色 |
| 同设备加入两个活动系统 | 拒绝 |
| 终端 ID 或手机号语义身份重复 | 拒绝注册 |
| 同车设备共享车牌 | 正常 |
| 普通车牌不一致 | 注册成功、系统降级、非阻塞告警 |
| 上报另一辆已存在车辆车牌 | 拒绝并告警 |
| 角色越权消息 | 不写业务事实，记录 `DEVICE_ROLE_VIOLATION` |
| 主源位置过期/隔离 | 切换到有效备源 |
| 两个来源都不可用 | 位置 `UNAVAILABLE` |
| WAN 出口设备离线 | 按各设备实际连接状态更新，不伪造联动状态 |

新增或复用审计原因：

- `VEHICLE_IDENTIFIER_MISMATCH`
- `VEHICLE_IDENTIFIER_CONFLICT`
- `DEVICE_ROLE_VIOLATION`
- `LOCATION_SOURCE_SWITCHED`
- `ONBOARD_DEVICE_ADDED/REMOVED`
- `ONBOARD_DEVICE_ROLE_ASSIGNED/REVOKED`
- `DEVICE_CAPABILITY_VERIFIED`
- `DEVICE_PROTOCOL_PROFILE_CHANGED`
- `WAN_UPLINK_CHANGED`

审计不保存真实终端号、手机号、车牌原文、鉴权码或摘要。

## 15. 安全边界

- 终端凭证和会话始终属于物理设备，不属于车辆聚合。
- `OnboardSystem` 不拥有可复用的公共鉴权码。
- 角色只能缩小设备可发送的业务范围，不能扩大协议身份权限。
- 共享 LAN 不授予设备互相冒用身份的权限。
- 设备故障、离线和重连必须分别审计。
- 管理端默认隐藏真实协议身份和网络敏感信息。
- 附件、视频凭证和媒体目标继续遵守 P6-2 既有不落库、不日志边界。

## 16. 测试先行矩阵

### 16.1 数据与迁移 RED

1. 旧单终端绑定可无损迁移，UUID、鉴权和审计不变。
2. 同车两个不同终端可成为活动成员。
3. 同设备不能加入两个活动系统。
4. 同系统不能存在两个 `DISPATCH`、`LOCATION_PRIMARY` 或 `ACTIVE_SAFETY`。
5. 主、备位置设备不能相同。
6. 角色没有已验证能力时拒绝。
7. 解除旧唯一索引前，缺失成员或角色会使迁移失败。
8. 重复终端手机号语义身份和终端 ID 继续被数据库拒绝。

### 16.2 注册与会话 RED

1. 同车两台独立设备同时注册、鉴权并保持两个会话。
2. 一台设备重连只替换自身旧连接。
3. 同车共享 `vehicle_identifier` 注册成功。
4. 普通车牌不一致返回 `APPROVED_WITH_WARNING`。
5. 上报另一车辆车牌被拒绝。
6. 跨连接鉴权返回 `onboardSystemId` 和角色快照。
7. SIM 所在设备变化不改变身份和会话归属。

### 16.3 位置 RED

1. 双设备位置原始事件都保留。
2. 主源有效时备源不能覆盖车辆快照。
3. 超过 `max(30 秒, 2 × 预期间隔)` 后切换到备源。
4. `QUARANTINED/REJECTED` 主源触发降级。
5. 主源恢复一条或两条时不切回，第三条有效位置才切回。
6. 迟到事件不能回滚快照。
7. 单记录仪和单调度终端均可成为主源。
8. 无定位能力时位置为 `UNAVAILABLE`。

### 16.4 角色与业务 RED

1. 非 `DISPATCH` 设备的调度消息被拒绝。
2. 非 `ACTIVE_SAFETY` 设备的报警不入库。
3. 非 `VIDEO` 设备不能执行媒体控制。
4. 无调度能力的记录仪车辆不进入调度车池。
5. 单调度终端车辆可调度，安全/视频为 `NOT_INSTALLED`。
6. 当前测试记录仪只有位置、安全和视频角色。

### 16.5 管理端与安全 RED

1. 聚合状态不掩盖设备级故障。
2. 设备操作只影响目标设备。
3. 角色/主备/WAN 变更需要版本、原因和权限。
4. 脱敏接口、日志、错误和公开报告不泄露身份或凭证。

### 16.6 完整回归

串行执行 JT 协议、gateway、API、模拟器、前端和私有脚本测试。总数不得低于当前 701 项基线，失败和错误均为 0。新增真实 PostgreSQL 双阶段迁移测试和双 TCP 连接模拟测试。

## 17. 部署与真实验收

### 17.1 部署顺序

1. 完成 RED/GREEN 和独立复核。
2. 停止态部署扩展阶段 API，gateway 保持停止、`7611` 无监听。
3. 备份数据库并执行 V19 扩展迁移。
4. 对现有对象运行私密 dry-run 和 role manifest 预检。
5. 应用成员、能力、协议档案和角色。
6. 验证兼容读取后部署支持多设备的 gateway。
7. 完成数据门禁后执行收口迁移，替换旧唯一约束。
8. 先模拟、后单设备、最后双设备真实验收。

### 17.2 真实验收顺序

1. 当前仅行车记录仪：注册、鉴权、位置、ADAS/DMS；车辆不可调度。
2. 接入调度终端：同车双会话、调度终端位置主源、记录仪备源。
3. 模拟主源失效和三条有效位置恢复。
4. 验证 SIM 在调度终端的共享网络。
5. 将 WAN 出口切到记录仪，确认身份和角色不迁移。
6. 验证仅调度终端车辆的调度与降级状态。

附件和真实媒体链路保持禁用，不作为本轮通过条件。

## 18. P6-2 边界调整

P6-2 增加：

- 车载系统聚合；
- 多物理设备身份与会话隔离；
- 能力角色；
- 位置主备；
- 单设备/双设备聚合管理；
- 车牌辅助校验和非阻塞告警。

P6-2 仍包含：

- 注册、鉴权；
- 位置上报；
- ADAS/DMS 报警；
- 当前测试行车记录仪真实验收。

P6-2 不包含：

- 完整 GB/T 28787 `0x0Bxx/0x8Bxx` 公交调度协议；
- 真实附件和媒体服务；
- RTP、录像存储、播放和转码；
- 将所有车辆强制升级为双设备。

完整公交国标业务协议另立后续阶段。本规格只为其提供设备、角色、会话和数据归属基础。
