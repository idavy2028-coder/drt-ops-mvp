# 订单与车辆任务按创建日期分组设计

## 背景

订单中心和车辆任务页当前把历史记录与新增记录放在同一张长列表中。试运行期间记录数量持续增加，运营人员难以快速定位当天新增订单、当前批次对应任务和历史异常记录。

## 目标

- 订单中心和车辆任务页都按“创建日期”分组展示。
- 当天创建的记录单独显示为“今日新增”，历史记录单独显示为“历史”。
- 保留现有状态、操作按钮、不可服务原因、任务选择和站点时间线行为。
- 不改变订单、任务、车辆资源或数据库状态，不通过前端隐藏历史数据。

## 设计方案

### 数据契约

后端订单视图 `RideOrderView` 和任务视图 `VehicleTaskView` 新增 `createdAt` 字段，值来自实体真实创建时间。前端 API 类型同步新增该字段。

订单分组不能使用 `requestedDepartureAt`，任务分组不能使用 `plannedStartAt`，因为这两个字段表示业务计划时间而不是记录创建时间。

### 前端分组

订单页和任务页分别计算两个分组：

- `today`: `createdAt` 转换为浏览器本地日期后等于当前日期。
- `history`: 其余记录。

每个分组显示独立标题和数量，并复用现有表格列与行渲染。分组内按 `createdAt` 倒序排列；当分组为空时显示“暂无今日新增订单/暂无历史订单”或对应任务文案。当前日期使用浏览器本地时区，确保运营端看到的“当天”与页面运行环境一致。

### 交互与兼容性

- 现有“录入需求”“刷新”“调度”“取消”“乘客未到”“选择”和任务执行按钮不变。
- 不新增筛选开关，不折叠或默认隐藏历史区域。
- 页面加载、刷新和提交订单后的重新加载继续使用同一分组计算逻辑。
- 旧接口若缺少 `createdAt`，前端不猜测计划时间作为替代；测试夹具和正式 API 一并补齐字段。

## 影响范围

- API：订单和任务读取视图及其测试。
- 前端：`OrdersPage.vue`、`TasksPage.vue`、对应 API 类型和页面测试。
- 不涉及数据库迁移；实体已有创建时间字段，只补充读取视图。

## 测试策略

测试先行覆盖以下行为：

1. 订单页把同一天和历史订单分别渲染到两个标题区域，并显示各自数量。
2. 任务页把同一天和历史任务分别渲染到两个标题区域，并保留选择按钮和状态。
3. 跨午夜边界按浏览器本地日期分组，不使用预计出发或计划发车时间。
4. 空分组显示对应空状态；现有不可服务原因展开和任务执行测试继续通过。
5. API 视图序列化 `createdAt`，前端类型检查和生产构建通过。

## 验收标准

- 订单中心可一眼区分“今日新增订单”和“历史订单”，历史记录不与今日记录混排。
- 车辆任务页可一眼区分“今日新增任务”和“历史任务”，车牌、状态、选择和站点时间线行为不回归。
- API、前端单元测试、类型检查和构建全部通过。
- 本地浏览器验收确认页面分区、数量、空状态和现有操作均正常。
