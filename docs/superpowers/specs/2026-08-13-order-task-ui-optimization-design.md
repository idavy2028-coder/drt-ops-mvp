# 订单中心与车辆任务页界面优化设计

- 文档状态：设计已确认，待实施计划
- 日期：2026-08-13
- 目标分支：`codex/admin-ui-optimization`
- 关联设计：`docs/superpowers/specs/2026-08-13-operations-dashboard-ui-optimization-design.md`

## 1. 背景

运营看板已按“通渭智慧公交”方向完成首屏指标、近 7 天趋势和分类占比优化。订单中心与车辆任务页仍存在以下问题：

- 页面纵向留白较多，今日与历史记录同时铺开后滚动距离长；
- 订单表缺少乘客电话和完整行程，调度员无法在列表内完成快速核对；
- 订单低频诊断信息挤高表格行，操作按钮随状态变化而错位；
- 车辆任务统计只覆盖运行和异常，无法一眼掌握待发车与已完成数量；
- 任务接口只返回车牌，不返回车辆权威状态，前端无法可靠展示“空闲/已派单/执行中”；
- 站点时间线显示原始站点标识和 ISO 时间，站名映射与时间表达不够清晰；
- 两页没有分页，也未被路由缓存，切换菜单后分页、选中任务和滚动位置会丢失。

本设计采用已确认的方案 A：订单中心使用“今日/历史分段表格 + 详情抽屉”，车辆任务使用“四项统计卡 + 左侧任务表 + 右侧执行步骤条”。

## 2. 目标

1. 在 1366×768 桌面视口内，让订单中心展示一页 8 条订单，让车辆任务页同时展示四项统计、最多 6 条任务和当前任务步骤条。
2. 订单列表直接提供乘客电话、上车点、下车点、状态、关键时间和高频操作。
3. 车辆任务列表使用后端返回的权威 `vehicleStatus`，不得根据任务状态猜测车辆状态。
4. 站点名称按 `virtualStopId` 精确映射，时间统一按 `Asia/Shanghai` 格式化。
5. 所有操作结果统一使用全局 Toast，并为取消订单等有副作用操作增加确认保护。
6. 菜单切换后保持订单分区和页码、任务分区和选中任务，以及两页各自的滚动位置。

## 3. 非目标

- 不修改订单或车辆任务的领域状态机。
- 不修改调度、乘客未到、车辆故障或严重延误的业务判定规则。
- 不增加数据库字段或数据库迁移；`vehicleStatus` 从既有车辆主数据实时读取。
- 不在本阶段增加后端分页协议，两个列表继续一次性读取现有接口数据并在前端分页。
- 不增加订单搜索、组合筛选、批量操作、导出或审计历史接口。
- 不重构与订单中心、车辆任务页无关的后台页面。

## 4. 视觉与密度规范

两页延续运营看板的高密度运营控制台视觉：深绿色导航、青绿色主操作色、低对比度分隔线和克制阴影。

| 项目 | 规格 |
| --- | --- |
| 页面区块间距 | 12px |
| 卡片内边距 | 16px |
| 表格表头/数据行最小高度 | 44px |
| 常规按钮最小高度 | 32px，触控目标通过周边间距保证可用性 |
| 面板圆角 | 8px，与现有后台一致 |
| 页面标题下间距 | 12px |
| 表格长文本 | 单元格内省略，完整内容通过原生提示或详情面板可见 |

状态颜色必须同时配合文字标签，不能只依赖颜色表达含义：

- 蓝色：待处理、已派单、待发车、执行中；
- 绿色：已确认、已完成、空闲或可用；
- 红色：不可服务、取消、异常、离线或不可用；
- 黄色：待人工复核等需要注意但尚未异常关闭的状态；
- 灰色：未知或尚未建立映射的状态。

### 5.2 今日与历史分区

- 页面只保留一张订单表，表格上方使用“今日新增”和“历史订单”分段按钮。
- “今日”按订单 `createdAt` 转换到 `Asia/Shanghai` 后的自然日判定，不使用预约出发时间，也不依赖浏览器本地时区。
- 分段按钮同时展示记录数，例如“今日新增 4”“历史订单 124”。
- 两个分区分别保存当前页码；切换分区时恢复该分区上次所在页。
- 刷新或操作后若当前页超过最新总页数，将页码收敛到最后一个有效页。

### 5.3 表格字段

| 列 | 内容 | 展示规则 |
| --- | --- | --- |
| 订单 | 短 ID、创建时间 | ID 显示前 8 位；创建时间显示 `HH:mm 创建` |
| 乘客 | 姓名、人数 | 两行展示，例如“张敏”“1 人” |
| 联系电话 | `passengerPhone` | 显示格式化号码，链接保留 `tel:` 加原始号码，无号码时显示 `--` |
| 上车点 → 下车点 | `originAddress`、`destinationAddress` | 两行展示并使用方向符号；空值显示“上车点未填写”或“下车点未填写” |
| 状态 | `status` | 使用统一 `StatusBadge` 颜色和中文标签 |
| 时间 | 预约、预计上车 | 同一单元格两行展示；无预计时间显示 `预计 --` |
| 操作 | 状态相关操作 | 固定顺序并限制单行最多三个有效按钮 |

### 5.4 订单状态映射

| 状态码 | 文案 | 色调 |
| --- | --- | --- |
| `PENDING_DISPATCH` | 待调度 | 蓝色 |
| `PENDING_MANUAL_REVIEW` | 待人工复核 | 黄色 |
| `CONFIRMED` | 已确认 | 绿色 |
| `IN_PROGRESS` | 执行中 | 蓝色 |
| `COMPLETED` | 已完成 | 绿色 |
| `UNSERVICEABLE` | 不可服务 | 红色 |
| `CANCELLED` | 已取消 | 红色 |
| `EXCEPTION_CLOSED` | 异常关闭 | 红色 |
| 未知状态 | 原始状态码 | 灰色 |

### 5.5 行内操作编排

`ORDER_READ` 用户始终可看到“查看详情”。变更类按钮继续受现有权限约束；没有 `DISPATCH_EXECUTE` 权限时不渲染调度、取消和异常处置操作。

有操作权限时按状态展示：

| 状态/条件 | 操作顺序 |
| --- | --- |
| 待调度 | 调度、查看详情、取消订单 |
| 执行中且可标记未到 | 查看详情、乘客未到、取消订单 |
| 执行中但未达到未到条件 | 查看详情、取消订单，并显示剩余等待提示 |
| 已取消 | 查看详情、确认乘客取消；取消订单保持禁用 |
| 其他可取消状态 | 查看详情、取消订单 |
| 已完成、不可服务、异常关闭 | 查看详情；取消订单保持禁用 |

“取消订单”在有操作权限的每行保持固定位置。终态订单使用禁用按钮，并通过 `aria-describedby` 提供不可取消原因，避免仅靠禁用样式传递信息。

### 5.6 详情抽屉

“查看详情”打开右侧抽屉，不离开当前列表。桌面端宽度为 420–480px；窄屏使用接近全宽的覆盖层。

抽屉展示：

- 完整订单编号；
- 乘客姓名、人数和可拨打电话；
- 完整上车点、下车点和请求类型；
- 创建、预约、预计上车和预计到达时间；
- 当前订单状态；
- 不可服务订单的摘要、候选方案数、等待/绕行阈值、拒绝原因、路线服务状态和诊断代码。

当前表格中的不可服务诊断展开块迁移到详情抽屉，防止单行高度超过 44px。抽屉支持关闭按钮、`Escape` 和遮罩关闭；打开后焦点进入抽屉，关闭后焦点返回触发按钮。

### 5.7 取消订单确认

- 点击“取消订单”后打开确认对话框，不直接调用接口。
- 对话框显示乘客、行程和当前状态，要求填写 2–100 字取消原因。
- 提交期间禁用重复提交和关闭动作。
- 成功后关闭对话框、刷新订单、保留当前分区和有效页码，并发送全局成功 Toast。
- 失败时保留对话框和输入内容，在对话框内展示错误，同时发送全局失败 Toast。

### 5.8 分页

- 使用客户端分页，固定每页 8 条。
- 分页作用于排序和分组完成后的结果；各分区均按 `createdAt` 倒序。
- 页脚显示“第 X / Y 页 · 共 N 条”、上一页和下一页。
- 无记录时显示对应分区的友好空状态，表格表头仍保留，便于理解字段结构。

```text
└───────────────────────────────────────┴─────────────────────────────┘
```

### 6.2 顶部统计卡

顶部使用四张紧凑统计卡：

- 执行中：任务状态为 `IN_PROGRESS`；
- 待发车：任务状态为 `DISPATCHED`；
- 异常：任务状态为 `EXCEPTION`；
- 已完成：任务状态为 `COMPLETED`。

每张卡显示“数量 + 占全部已加载任务比例”，比例保留一位小数；总任务数为 0 时显示 `0 项 · 0.0%`。当前领域状态由上述四类构成。未来出现未知状态时，列表仍以灰色展示原始状态码，统计卡不把未知状态错误归类，因此四项比例允许暂时小于 100%。

### 6.3 任务分区与表格

- 今日与历史任务使用分段按钮，一次显示一个分区。
- “今日”按 `createdAt` 转换到 `Asia/Shanghai` 后判定。
- 每个分区独立保存页码和最后选中的任务。
- 默认每页 6 条，按 `createdAt` 倒序。

任务表字段：

| 列 | 内容 | 展示规则 |
| --- | --- | --- |
| 任务 | 短 ID | 显示前 8 位 |
| 车辆/车辆状态 | 车牌、`vehicleStatus` | 两行展示，车辆状态使用独立标签 |
| 最新位置 | 人工上报时间、标准化地址 | 无快照显示“暂无位置上报” |
| 任务状态 | `status` | 使用统一状态标签 |
| 计划发车 | `plannedStartAt` | 显示 `MM-DD HH:mm` |
| 操作 | 选择 | 当前行显示“已选择”，其他行显示“选择” |

页面首次加载时选择当前分区第一项。若 URL 带有有效 `taskId`，页面自动切换到任务所在分区和页码并选中该任务，保留现有从其他页面深链到任务的能力。

### 6.4 `vehicleStatus` 接口契约

在 `VehicleTaskView` 中新增可空字段：

```text
UUID vehicleId
String vehiclePlateNumber
String vehicleStatus
UUID driverId
TaskStatus status
...
```

接口影响范围：

- `GET /api/vehicle-tasks`；
- 发车、到站、上车、下车和完成动作返回的 `TaskActionView.task`；
- 车辆故障、严重延误返回的 `VehicleTaskView`。

`VehicleTaskController.toView` 对每项任务只执行一次既有车辆查询，并从同一个车辆对象读取车牌和 `currentStatus`。车辆记录不存在时，`vehiclePlateNumber` 和 `vehicleStatus` 均返回 `null`。本变更不新增数据库字段，也不从任务状态推导车辆状态。

前端 `VehicleTask.vehicleStatus` 采用可选字段，以兼容旧响应和已有测试夹具；缺失时显示“状态未知”。

车辆状态映射：

| 状态码 | 文案 | 色调 |
| --- | --- | --- |
| `IDLE` | 空闲 | 绿色 |
| `DISPATCHED` | 已派单 | 蓝色 |
| `IN_SERVICE` | 执行中 | 蓝色 |
| `OFFLINE` | 离线 | 红色 |
| `UNAVAILABLE` | 不可用 | 红色 |
| 兼容值 `AVAILABLE` | 可用 | 绿色 |
| 未知或空值 | 状态未知 | 灰色 |

### 6.5 当前任务面板

右侧面板展示当前任务短 ID、车牌、车辆状态和任务状态。任务执行按钮从左侧列表底部迁移到当前任务面板底部，使操作与选中对象保持在同一视觉上下文。

动作分两组：

- 正常执行：发车、到站、上车、下车、完成；
- 异常处置：车辆故障、严重延误。

按钮继续沿用现有状态门禁和 `TASK_EXECUTE` 权限控制，不改变领域规则。需要位置确认的动作继续打开现有 `LocationReportPanel`；成功后更新当前任务并保持选择，失败时不切换任务。所有结果使用全局 Toast。

### 6.6 站点步骤条

步骤条按以下顺序生成：

1. 复制任务站点数组并按 `sequenceNumber` 升序排序；
2. 以 `virtualStopId` 为键构建虚拟站点名称映射；
3. 每个步骤通过自身 `virtualStopId` 查找名称，禁止按数组下标或相邻位置推断；
4. 找不到对应站点时显示“未知站点 · `xxxxxxxx`”，其中 `xxxxxxxx` 为站点 ID 前 8 位。

视觉状态：

- 已完成步骤使用绿色实心节点和连线；
- 当前可执行步骤使用蓝色节点和柔和外环；
- 后续步骤使用灰色空心节点；
- 每个节点同时显示站名、上车站/下车站、执行状态和时间文案。

时间文案：

| 站点状态 | 文案 |
| --- | --- |
| `PLANNED` | `计划到站 HH:mm` |
| `ARRIVED` | `已到站 HH:mm` |
| `BOARDED` | `已到站 HH:mm · 已上车` |
| `ALIGHTED` | `已到站 HH:mm · 已下车` |

`ARRIVED`、`BOARDED` 和 `ALIGHTED` 使用现有 `actualArrivalAt`。现有模型没有独立的上车或下车发生时间，因此不得把计划时间伪装成实际操作时间。时间缺失或无法解析时显示 `--`，页面不得输出原始 ISO 字符串或 `Invalid Date`。

### 6.7 分页与选择保持

- 使用客户端分页，固定每页 6 条。
- 每个分区保存独立页码和最后选择的任务 ID。
- 切换分区时优先恢复该分区上次选中的任务；任务已不存在时选择当前页第一项。
- 刷新或任务动作后，若任务仍存在则保持选择；若任务从今日分区移动或不再存在，则重新计算分区、页码和默认选择。

### 6.8 降级与错误处理

任务页的三组读取请求独立处理：

- 任务列表失败：页面展示错误和“重新加载”按钮，不展示统计或任务步骤；
- 虚拟站点失败：任务表和动作仍可使用，步骤条站名降级为短 ID；
- 最新位置失败：位置列显示“暂无位置上报”，不阻断任务动作；
- `vehicleStatus` 缺失：显示“状态未知”，不根据任务状态补造；
- 用户主动刷新失败：保留最近一次成功数据，并发送全局失败 Toast。

## 7. 页面状态保持

当前 `AppLayout` 直接渲染 `RouterView`，菜单切换会销毁页面组件。本阶段为订单中心和车辆任务路由增加缓存能力：

- 在两条路由的 `meta` 中标记 `keepAlive: true`；
- `AppLayout` 使用 `RouterView` 插槽和 Vue `KeepAlive` 缓存已标记页面；
- 订单页组件状态保存当前分区、两个分区的页码、打开的详情和未提交的取消原因；
- 任务页组件状态保存当前分区、两个分区的页码、各分区最后选择的任务和位置确认表单输入；
- 页面停用时记录 `window.scrollY`，重新激活后在 `nextTick` 恢复滚动位置；
- 退出登录时组件随应用会话结束销毁，不跨用户复用缓存。

缓存恢复时不自动重新加载数据，避免菜单切换清空表单或改变列表。用户点击“刷新”时才主动同步；首次进入页面仍正常加载数据。

## 8. 组件边界

为避免两个页面继续膨胀，实施时按职责拆分：

| 单元 | 职责 |
| --- | --- |
| `OrdersPage.vue` | 数据加载、今日/历史分组、分页状态、权限和动作编排 |
| `OrderDetailDrawer.vue` | 只负责订单详情展示和焦点管理，不发起数据请求 |
| `OrderCancelDialog.vue` | 取消原因校验、确认/关闭事件，不直接调用 API |
| `TasksPage.vue` | 数据聚合、统计、分区分页、任务选择和动作编排 |
| `TaskStopTimeline.vue` | 接收已排序的站点和名称映射，渲染步骤状态与时间 |
| `RecordPagination.vue` | 订单和任务共用的紧凑分页栏，仅接收页码、总数和事件 |
| 日期展示工具 | 统一上海时区、空值和非法值处理 |
| 页面滚动保持组合函数 | 记录并恢复缓存页面的滚动位置 |

组件通过明确的 props 和事件通信；详情抽屉、取消对话框和分页组件不得直接依赖页面 API 模块。

## 9. 数据流

### 9.1 订单中心

```text
GET /api/orders
  → 按 createdAt 倒序
  → 按上海自然日分为今日/历史
  → 选择当前分区
  → 按每页 8 条切片
  → 表格
  → 详情抽屉或状态相关动作
  → 操作成功后重新读取，同时保留有效页面状态
```

### 9.2 车辆任务

```text
GET /api/vehicle-tasks ───────────────┐
GET /api/virtual-stops ─→ 站名映射 ──┼→ 分组/分页/统计 → 任务表 + 当前任务步骤条
GET /api/vehicles/locations/latest ───┘

任务动作
  → 位置确认
  → TaskActionView.task（含 vehicleStatus）
  → 原位更新任务
  → 重新计算统计和当前步骤
```

## 10. 响应式与可访问性

- 宽度大于 1180px：车辆任务采用左右双栏；订单详情使用右侧抽屉。
- 900–1180px：任务右侧面板缩窄，表格在自身容器内横向滚动。
- 小于 900px：统计卡变为 2×2，任务表和步骤条上下堆叠，详情抽屉接近全宽。
- 表格、按钮、抽屉和对话框保持自然键盘顺序。
- 图标按钮必须有可见文字或 `aria-label`。
- 状态、选中和禁用均同时使用文字或辅助说明，不只依赖颜色。
- 电话链接的可访问名称包含完整号码。
- 抽屉和对话框打开时管理焦点，关闭后恢复到触发控件。

## 12. 测试设计

### 12.1 前端订单测试

1. 展示乘客电话，链接 `href` 使用未经格式化破坏的 `tel:` 值。
2. 同时展示上车点和下车点，空值有明确回退文案。
3. 状态码映射到预期文案和色调。
4. 今日/历史严格按上海时区下的 `createdAt` 分组。
5. 每页最多 8 条，两个分区页码独立，数据减少后页码收敛。
6. “查看详情”打开包含完整字段和不可服务诊断的抽屉。
7. 可取消订单必须经过确认和原因校验；终态订单不能调用取消接口。
8. 调度、乘客未到、确认乘客取消等既有能力和权限门禁不回归。
9. 操作成功和失败均触发全局 Toast。

### 12.2 前端任务测试

1. 四张卡正确计算执行中、待发车、异常、已完成数量和比例。
2. 展示车牌和接口返回的 `vehicleStatus`；缺失时显示“状态未知”。
3. 今日/历史按上海时区下的 `createdAt` 分组，每页最多 6 条。
4. `taskId` 深链自动定位正确分区、页码和任务。
5. 站点按 `sequenceNumber` 排序并按 `virtualStopId` 映射名称。
6. 虚拟站点缺失时显示短 ID，不错配其他站名。
7. 计划和实际时间按上海时区格式化，非法时间不显示 `Invalid Date`。
8. 站点步骤的完成、当前和后续视觉语义正确。
9. 任务动作、位置确认、权限门禁和现有响应兼容逻辑不回归。
10. 任务、站点和位置三类请求分别验证失败降级行为。

### 12.3 页面缓存测试

1. 从订单中心切换菜单再返回，分区、页码、抽屉/取消表单和滚动位置保持。
2. 从车辆任务切换菜单再返回，分区、页码、选中任务、位置表单和滚动位置保持。

### 12.4 后端测试
