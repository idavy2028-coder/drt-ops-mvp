# P6-2 实时车辆定位与主动安全接入设计

日期：2026-08-12（Asia/Shanghai）

状态：设计已完成，等待人工复核

## 1. 目标、决策与边界

### 1.1 目标

P6-2 建设一个独立的、基于 Netty 的部标协议网关，将 4 台主动安全行车记录仪接入现有网约公交运营系统，并形成以下闭环：

1. JT/T 808—2019 主版本及 2013 公共定位链路兼容；
2. 终端白名单注册、鉴权、车辆强绑定和在线会话管理；
3. 实时位置接入、WGS84 到 GCJ-02 标准化、位置质量治理和调度快照更新；
4. T/JSATL12 苏标主动安全报警解析、存储、实时看板和基础处置；
5. 主动安全报警附件及 JT/T 1078 文件上传控制信令；
6. 与外部媒体/文件服务器解耦，不在本期承载媒体二进制流。

当前试点接入 4 台终端，设计容量为 100 个并发 TCP 连接。执行任务时每 10 秒上报位置，空闲时每 60 秒上报，心跳间隔为 60 秒。

### 1.2 已确认决策

- 采用“共用网关，内部分流”：808、苏标扩展和 1078 控制信令共用部署、终端身份和鉴权会话，内部按协议模块分流。
- 终端采用预置白名单强绑定，不允许陌生设备自动创建车辆或绑定。
- P6-2 以 JT/T 808—2019 为主，公共定位链路兼容识别 2013；T/JSATL12 按其基于 JT/T 808—2013 的扩展进行解析。
- 位置采用 `GOOD`、`WARNING`、`QUARANTINED`、`REJECTED` 四级处理，不使用不可解释的综合质量分数。
- 位置继续写入现有不可变事件体系；报警事实、处置动作和附件元数据使用独立追加式模型。
- 位置在管理端维持 10 秒轮询；主动安全报警使用 SSE 实时推送，失败时退化为 5 秒轮询。
- ETA 继续标注“仅作参考”，P6-2 不将其升级为运营指标。

### 1.3 协议口径修正

`0x1206` 不是苏标主动安全报警本体。在公开实现的协议清单中，它属于 JT/T 1078 文件上传完成通知。P6-2 按以下边界实现：

- 苏标主动安全报警事实：解析带 T/JSATL12 扩展信息的 `0x0200`；
- 主动安全报警附件：`0x9208`、`0x1210`、`0x1211`、`0x1212`、`0x9212`；
- JT/T 1078 文件上传控制兼容：`0x9206`、`0x9207`、`0x1206`。

参考项目：

- [yezhihao/jt808-server](https://github.com/yezhihao/jt808-server)：Netty 接入、协议与服务分层、多版本和苏标/1078 扩展；
- [cuteLittleDevil/go-jt808](https://github.com/cuteLittleDevil/go-jt808)：主动安全附件消息链路清单；
- [Netty](https://github.com/netty/netty)：异步事件驱动网络框架。

本项目只参考架构和协议组织方式，独立实现业务模型与安全约束，不复制第三方业务代码。实施时必须固定依赖版本、核对许可证并完成依赖漏洞扫描。

### 1.4 方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 共用 Netty 网关、协议模块内部分流 | 身份、会话和限流统一；协议扩展边界清楚；适合 100 连接试点 | 网关模块边界必须严格，避免媒体逻辑侵入 I/O 线程 | 采用 |
| 808、苏标、1078 各自独立网关 | 服务隔离彻底 | 重复会话和终端管理；试点运维成本高 | 不采用 |
| 将 Socket 接入嵌入现有运营 API | 初期组件少 | 长连接 I/O、协议状态和业务事务强耦合，故障域扩大 | 不采用 |

### 1.5 明确不包含

P6-2 不实施：

- JT/T 1078 媒体接收、RTP 处理、转码、录像、存储和播放；
- 自建流媒体服务器；
- JT/T 808 UDP、2011 版本及全量下行控制指令；
- 粤标等其他地方主动安全标准的消息解析，只预留扩展接口；
- Kafka/RabbitMQ、多实例分布式会话和千级终端集群；
- 公网生产部署批准；
- 道路匹配、轨迹纠偏、完整轨迹回放和机器学习预测；
- 将 ETA 升级为硬性运营指标。

## 2. 终端注册、鉴权与强绑定

### 2.1 终端预置

系统管理员必须先录入终端手机号、终端 ID、制造商 ID、型号、协议组合、原始坐标系和绑定车辆。终端手机号与终端 ID 全局唯一；一辆车同一时刻只能绑定一个启用终端，一台终端同一时刻只能绑定一辆车。

终端能力使用明确组合登记，例如：

- `JT808_2019`；
- `JT808_2013`；
- `JT808_2013 + JSATL12_2017 + JT1078_2016`。

网关不得仅凭消息长度、车牌或消息 ID 猜测地方标准。

### 2.2 注册与鉴权

1. TCP 建连后会话进入 `CONNECTED_UNAUTHENTICATED`，30 秒内只接受 `0x0100` 注册或 `0x0102` 鉴权。
2. 网关根据消息头识别 2019/2013，并选择对应解码器。
3. `0x0100` 必须同时核对终端手机号、终端 ID、制造商、型号和车辆标识；不得仅凭车牌绑定。
4. 白名单匹配成功后生成高强度随机鉴权码，通过 `0x8100` 返回；数据库只保存鉴权码摘要和版本。
5. 未登记、已停用、字段不匹配或车辆绑定失效时返回明确失败结果，记录安全审计并关闭连接。
6. `0x0102` 验证成功后会话进入 `AUTHENTICATED`，此后才接受心跳、位置、苏标报警和附件信令。
7. 连续三次鉴权失败立即断开并产生安全告警。

鉴权码明文不得落库、写日志、进入指标或通过管理 API 返回。网关重启后终端必须重新鉴权。

### 2.3 会话与重复登录

- 活跃会话以平台登记的终端身份为键，不信任报文车牌来查找车辆。
- 同一终端新连接鉴权成功后由新会话接管，旧连接关闭，并记录远端地址、时间和原因。
- 60 秒为预期心跳间隔；连续 180 秒无有效报文则标记离线并关闭连接。
- 每条已鉴权消息只能作用于终端当前绑定的车辆；身份与会话不一致时整包拒绝。
- 注册、鉴权、上下线、重复登录、停用、换机和拒绝结果进入独立安全审计。

### 2.4 换机

换机必须在同一业务事务中关闭旧绑定、创建新绑定、轮换鉴权码并追加审计。历史绑定不得直接覆盖。旧终端的活跃会话立即关闭，旧鉴权版本立即失效。

## 3. Netty 网关与协议分流

### 3.1 服务边界

新增独立 Java 21 服务 `jt-gateway`，使用受控版本的 Netty：

- 网关负责 TCP 连接、帧处理、协议编解码、版本识别、分包重组、终端会话、协议应答和持久化投递缓冲；
- 运营 API 负责终端档案、坐标转换、质量规则、围栏、不可变位置事件、报警事实、车辆快照、调度消费和管理端 API；
- 外部媒体/文件服务器负责附件二进制接收、存储、临时访问和生命周期；
- 网关不得直接修改车辆、订单、任务或运营数据库中的位置/报警表。

“共用网关”不意味着全部流量共用一个端口或同一 EventLoop。P6-2 的 808 控制入口使用可配置的 `7611/TCP`；媒体数据端口属于外部媒体服务器。

### 3.2 Netty 处理链

处理链依次为：

1. 连接数、单 IP 速率和空闲超时控制；
2. `0x7e` 帧拆分、转义还原和最大报文长度限制；
3. 校验码验证；
4. 2019/2013 消息头识别；
5. 分包缓存、重组、超时清理及必要的补传；
6. 消息编解码注册表；
7. 白名单会话鉴权；
8. 按协议模块和消息 ID 分发；
9. 有界业务队列和背压。

Netty I/O 线程只执行轻量解析，不执行数据库、HTTP、文件或媒体阻塞调用。工作队列达到高水位时暂停读取；持续拥塞时关闭连接并告警，不允许无限堆积。

### 3.3 协议模块

- `Jt808CoreModule`：`0x0100`、`0x0102`、`0x0002`、`0x0200`、平台通用应答及分包处理；
- `Jsatl12ActiveSafetyModule`：按终端能力档案解析 T/JSATL12 的 `0x0200` 主动安全扩展；
- `Jt1078ControlModule`：音视频与文件上传控制消息路由；
- `ActiveSafetyExtensionSPI`：为粤标等其他标准预留解码器、规范化映射和能力声明接口，默认没有实现。

### 3.4 位置规范化

`0x0200` 的标准位置主体转换为 `CanonicalPositionIngress`，包含：

- 终端和会话身份、协议版本、消息流水号；
- 原始坐标和坐标系；
- 报警位、状态位、速度、方向、海拔及可选卫星数；
- 终端定位时间、网关接收时间、报文摘要。

### 3.5 苏标报警规范化

收到 `0x0200` 后先解析标准位置主体，再依据终端档案选择苏标解析器。一条位置消息可以生成一条位置事件和多条 `CanonicalVehicleAlarm`。

规范化报警至少包含：

- `ADAS` 或 `DMS` 模块；
- 原始报警类型代码、名称快照、等级和开始/结束状态；
- 终端报警标识和发生时间；
- 坐标、速度及车辆状态；
- 附件数量、附件请求标识和原始扩展摘要。

报警幂等键由终端、标准、报警标识、报警类型、开始时间和报文摘要生成。基础位置有效但苏标扩展损坏时，位置仍进入质量流程，报警扩展单独拒绝并审计；平台向终端返回成功，避免整帧无限重传。位置被隔离时，报警事实仍需保留并标记位置质量，不得因定位质量问题丢弃安全事件。

未知但结构合法的苏标报警类型保存原始代码并显示“未知报警类型”，不得丢弃，也不得擅自映射成其他类型。

### 3.6 业务投递与应答

网关采用“内部 HTTP + 本地持久化缓冲”，不在 P6-2 引入消息队列：

- 规范化位置、报警和附件元数据先写入网关本地持久化缓冲，成功后才向终端完成相应协议应答；
- 位置按最多 50 条或最长 1 秒批量投递，报警和附件状态使用独立高优先级队列，禁止被位置批次饿死；
- 网关通过服务级凭证调用运营 API，不使用调度员 JWT；
- API 不可用时指数退避，恢复后按接收顺序补投；
- API 按幂等键去重；
- 缓冲达到容量上限或写入失败时停止读取并产生严重告警，不向终端伪造成功。

### 3.7 报警附件控制

主动安全附件支持 `0x9208`、`0x1210`、`0x1211`、`0x1212`、`0x9212`；JT/T 1078 文件控制兼容支持 `0x9206`、`0x9207`、`0x1206`。

1. 运营 API 创建附件请求；
2. 外部媒体服务通过 `AlarmAttachmentMediaPort` 返回一次性上传目标；
3. 网关向在线终端下发上传指令；
4. 终端向外部服务器上传二进制；
5. 网关接收附件信息、文件信息和完成通知；
6. 媒体服务使用验签回调确认文件；
7. API 更新附件状态并关联报警。

网关只传递控制信令和元数据，不代理或落盘附件二进制。上传凭证、长期有效 URL 和完整外部存储路径不得进入网关日志、报警表或 SSE。

外部媒体服务不可用时，报警照常创建，附件标记为 `WAITING_MEDIA_SERVICE`，管理端显示“报警已收到、附件暂不可用”。媒体故障不得阻断普通位置和报警事实接入。

### 3.8 可观测性

指标至少包括：连接数、在线终端、协议版本/消息 ID 数量、鉴权失败、校验失败、分包超时、解码耗时、队列深度、补投数量、API 投递延迟、位置四级质量数量、报警类型/等级数量、附件请求成功率和 SSE 活跃连接。

健康检查区分：进程存活、TCP 监听可用、持久化缓冲可写、运营 API 可投递和外部媒体服务可用。媒体服务不可用只降低附件能力健康状态，不把位置接入判定为不可用。

## 4. 数据模型与兼容迁移

### 4.1 终端主表 `jt_terminals`

主要字段：

- `id`、`terminal_phone`、`terminal_code`；
- `manufacturer_id`、`model`；
- `protocol_version`、`source_coordinate_system`；
- `active_safety_standard`、`active_safety_modules`、`jt1078_enabled`；
- `attachment_upload_profile`、`media_server_profile_id`；
- `status`：`PENDING`、`ACTIVE`、`SUSPENDED`、`RETIRED`；
- `auth_token_hash`、`auth_token_version`；
- `last_registered_at`、`last_authenticated_at`、`last_seen_at`；
- `created_by`、`created_at`、`updated_at`、`version`。

终端手机号与终端 ID 全局唯一。终端手机号在普通页面和日志中脱敏显示。粤标等未实现能力只能登记，不能启用解析。

### 4.2 绑定历史 `jt_terminal_vehicle_bindings`

记录 `terminal_id`、`vehicle_id`、`valid_from`、`valid_to`、状态、绑定/解绑原因、操作人和操作时间。部分唯一索引保证每台终端和每辆车最多各有一条有效绑定。

### 4.3 网关安全审计 `jt_gateway_audit_events`

记录注册、鉴权、上下线、重复登录、停用、换机、协议拒绝、限流和强制断开。字段包括终端/车辆、事件类型、结果、原因码、协议版本、消息 ID、报文摘要、远端地址、发生时间和网关实例。无法解析出可信身份的非法报文只写该表，不生成位置或报警事件。

### 4.4 扩展 `vehicle_location_events`

保留现有不可变位置事件表，新增：

- `terminal_id`、`protocol_version`、`message_serial_no`；
- `raw_longitude`、`raw_latitude`、`raw_coordinate_system`；
- `gateway_received_at`、`payload_digest`；
- `speed_kph`、`direction_degrees`、`altitude_meters`、`satellite_count`；
- `alarm_bits`、`status_bits`；
- `coordinate_transform_version`；
- `quality_status`、`quality_reasons JSONB`。

现有 `driver_reported_at` 物理列保留，在领域模型中解释为“来源报告时间”，GPS 事件中等于终端定位时间。

约束调整：

- `MANUAL_DISPATCHER` 必须有 `recorded_by`，`terminal_id` 为空；
- `GPS_DEVICE` 必须有 `terminal_id`，`recorded_by` 允许为空；
- 人工位置必须有地址；GPS 位置地址允许为空；
- 不为每个实时 GPS 点强制执行逆地理编码。

### 4.5 位置质量和快照

终端原始坐标、原始坐标系和报文摘要必须保留；业务地图、围栏、调度和路径服务只使用标准化 GCJ-02。WGS84 只转换一次，GCJ-02 不重复转换，并记录转换算法版本。

每条位置记录终端定位时间、网关接收时间和业务落库时间：

- 接收延迟不超过 30 秒：正常；
- 30–120 秒：警告，可更新快照；
- 超过 120 秒或终端时间超前超过 120 秒：隔离，不更新快照；
- 乱序事件保留，但不得覆盖时间更新的快照。

四级处理：

| 等级 | 行为 |
| --- | --- |
| `GOOD` | 写入历史并更新快照 |
| `WARNING` | 写入历史、更新快照并展示原因 |
| `QUARANTINED` | 写入历史，不更新快照、不参与调度 |
| `REJECTED` | 不生成位置事件，只记录协议拒绝审计和指标 |

校验码错误、非法时间、越界/零坐标、未鉴权和身份不一致直接拒绝。定位无效、超过 140 km/h、推算移动速度超过 180 km/h、严重时间异常进入隔离。服务区外、30–120 秒延迟、120–140 km/h 或缺少可选字段产生警告。

`vehicles` 最新快照增加终端、质量等级/原因、网关接收时间、速度、方向和陈旧状态。只有时间更新且质量为 `GOOD/WARNING` 的事件可以更新快照。人工位置链路继续保留，终端离线或异常时可人工降级。

### 4.6 报警事实 `vehicle_alarms`

主要字段：

- `id`、`vehicle_id`、`terminal_id`；
- 可空的 `location_event_id`、`vehicle_task_id`；
- `standard`、`module`、`alarm_type_code`、`alarm_type_name_snapshot`；
- `alarm_level`、`terminal_alarm_identifier`；
- `terminal_alarm_state`：`START`、`END`；
- `occurred_at`、`ended_at`、`gateway_received_at`；
- 坐标、速度和 `location_quality_status`；
- `processing_status`：`NEW`、`ACKNOWLEDGED`、`PROCESSING`、`RESOLVED`、`FALSE_POSITIVE`；
- `payload_digest`、`deduplication_key`；
- `handled_by`、`handled_at`、`version`。

一个位置事件可关联多个报警。无法形成可信位置事件时，报警仍保存自身坐标和质量原因。报警类型、终端标识、发生时间、位置和报文摘要等事实字段不可更新或删除；数据库约束只允许受控更新处理状态、处理人、处理时间和乐观锁版本，全部状态变化同时追加到动作表。

### 4.7 报警处置 `vehicle_alarm_actions`

追加式记录确认、接手、备注、请求附件、解决、标记误报和受控重开，包括前后状态、操作人、时间和原因。

允许状态转换：

- `NEW → ACKNOWLEDGED | FALSE_POSITIVE`；
- `ACKNOWLEDGED → PROCESSING | RESOLVED | FALSE_POSITIVE`；
- `PROCESSING → RESOLVED | FALSE_POSITIVE`；
- 只有系统管理员可将终态重开为 `PROCESSING`，必须填写原因并追加审计。

并发更新使用乐观锁；冲突返回明确的 409，不覆盖他人处置。

### 4.8 报警附件 `vehicle_alarm_attachments`

保存报警、附件类型、通道、媒体格式、清洗后文件名、大小、校验摘要、外部媒体引用，以及：

- `WAITING_MEDIA_SERVICE`；
- `REQUESTED`；
- `UPLOADING`；
- `AVAILABLE`；
- `FAILED`；
- `EXPIRED`。

数据库不保存大文件、二进制、上传凭证或长期播放 URL。查看附件时由媒体服务按权限签发短时地址。

`vehicle_alarm_attachment_transfers` 记录平台和终端流水号、控制消息类型、外部目标引用、重试次数、状态、错误码和时间。同一附件同时只能有一个活动传输任务。

### 4.9 报警 Outbox 与 SSE

`vehicle_alarm_outbox` 与报警事实/处置动作在同一事务写入。发布器读取 Outbox 后向 SSE 订阅者发送脱敏事件；成功发布后标记完成，失败可重试。SSE 事件不包含附件临时 URL、手机号、完整终端 ID、报文正文或鉴权信息。

客户端使用 `Last-Event-ID` 补读；超过保留窗口则重新拉取报警列表。Outbox 事件保留 7 天，清理由受控任务完成。

### 4.10 网关投递缓冲

网关使用独立持久化缓冲，记录幂等键、规范化 DTO、创建时间、投递次数、下次重试时间、错误码和 `PENDING/DELIVERING/DELIVERED/DEAD_LETTER`。运营 API 确认后删除正文并保留短期指标；死信保留 7 天，不保存鉴权信息和媒体凭证。

### 4.11 迁移兼容

Flyway 分阶段执行：

1. 创建终端、绑定、安全审计表；
2. 扩展位置事件和车辆快照；
3. 创建报警、处置、附件、传输和 Outbox 表；
4. 增加权限及索引。

历史人工位置回填为 `quality_status=GOOD`，原始坐标等于现有 GCJ-02，转换版本为 `LEGACY_NONE`，GPS 字段为空。原有人工上报、历史、导出和调度接口保持兼容。

增加终端时间、质量、报警状态/时间、附件状态及车辆维度索引，并为大时间表增加 BRIN 索引。P6-2 不立即分区；真实终端超过 20 台或高频数据连续运行 90 天前，单独评估分区迁移。

## 5. 管理端、权限与运维

### 5.1 新增权限

- `TERMINAL_READ`：查看脱敏终端档案、绑定和在线状态；
- `TERMINAL_MANAGE`：预置、绑定、换机、停用、鉴权轮换和强制断开；
- `VEHICLE_ALARM_READ`：查看报警事实和处置记录；
- `VEHICLE_ALARM_HANDLE`：确认、接手、解决、标记误报和填写处置记录；
- `VEHICLE_ALARM_ATTACHMENT_REQUEST`：发起或重试报警附件上传；
- `VEHICLE_ALARM_ATTACHMENT_READ`：获取经鉴权的短时附件查看地址。

角色矩阵：

| 角色 | 终端 | 报警 | 附件 |
| --- | --- | --- | --- |
| `SYSTEM_ADMIN` | 查看和管理 | 查看和处置，可受控重开 | 请求和查看 |
| `DISPATCHER` | 不进入终端管理；通过位置权限查看在线状态 | 查看和基础处置 | 请求和查看 |
| `OPERATOR` | 无 | 只读 | 无 |
| `AUDITOR` | 无 | 只读，并可查看脱敏处置审计 | 无 |

终端管理、终态处置、误报、附件请求和受控重开必须二次确认并填写原因。管理接口在服务层再次校验权限，不只依赖前端隐藏按钮。

### 5.2 终端管理页

支持预置、绑定、激活、暂停、退役、换机、轮换鉴权码、强制断开，以及查看最近注册、鉴权、心跳、位置、离线时间、绑定历史和安全审计。不得展示完整终端手机号、鉴权码、完整报文或内部 UUID。

### 5.3 调度工作台报警看板

在地图工作台增加独立报警区域，不挤占地图主视野：

- 未确认报警数量、最高等级和最近发生时间；
- 按等级、状态、车辆、ADAS/DMS、是否有附件筛选；
- 新报警置顶并在对应车辆标记上显示非闪烁状态徽标；
- 点击报警后地图聚焦车辆位置，侧栏显示车牌、报警类型、等级、发生时间、速度、位置质量和附件状态；
- 基础操作包括确认、接手、备注、请求附件、解决和标记误报；
- 不显示完整终端标识、原始报文、内部 UUID 或永久媒体地址。

报警位置为 `QUARANTINED` 时必须显示“位置可疑”，但报警本身仍正常进入处置队列。附件不可用不得隐藏报警。

### 5.4 SSE 推送与降级

- 报警 SSE 使用现有登录身份和 `VEHICLE_ALARM_READ` 权限；
- 每条事件再次按用户权限过滤；
- 支持 `Last-Event-ID`、15 秒心跳和指数退避重连；
- SSE 只推送报警摘要及状态变更，详情通过受权 REST API 查询；
- SSE 断开，或浏览器、反向代理不支持长连接时，自动退化为 5 秒轮询，并在页面显示“实时推送已降级”；
- 位置仍使用 10 秒轮询，不在 P6-2 改造成连续推送。

### 5.5 附件安全

- 附件请求前检查报警、终端在线状态、终端能力、用户权限和当前活动传输；
- 外部媒体服务返回一次性上传目标和短时查看 URL；
- 回调必须验签、防重放并核对文件摘要和大小；
- 文件名必须清洗，类型和大小使用白名单限制；
- 附件默认不可公开访问；
- 附件查看、下载和失败重试均写审计；
- 媒体服务不健康时禁止创建无法执行的上传任务，改为 `WAITING_MEDIA_SERVICE`。

### 5.6 网络与密钥安全

- `7611/TCP` 是唯一面向终端的网关入口；管理、健康和指标端口只允许容器网络或管理网访问；
- 优先使用专用 APN、VPN 或固定来源防火墙；JT/T 808 原始 TCP 不提供传输机密性，公网试运行前必须另行完成网络安全评估；
- 网关服务凭证和媒体回调密钥通过环境密钥或密钥文件注入，不进入 Git、镜像或日志；
- 服务凭证支持双版本轮换；
- 1078 媒体端口不由本系统监听。

### 5.7 告警等级与处置

| 等级 | 场景 | 处理 |
| --- | --- | --- |
| 严重 | 网关不可用、缓冲满、API 投递中断、报警附件控制持续失败 | 停止伪成功；人工介入；位置转人工流程；报警事实继续保留 |
| 重要 | 执行中车辆离线、连续 3 个位置隔离、高等级主动安全报警、鉴权攻击 | 工作台置顶；调度员确认并联系驾驶员 |
| 提醒 | 空闲车辆位置陈旧、服务区外、时钟偏差、附件暂不可用 | 标注状态并进入待处理列表 |

同一终端和原因只保留一个活动技术告警；恢复后自动关闭并写恢复审计。主动安全业务报警按终端报警标识独立去重，不与网关技术告警混用。

### 5.8 运维手册

P6-2 必须交付终端预置、首次接入、换机、停用、密钥轮换、端口检查、离线排查、坐标异常、报警处置、附件失败、SSE 降级、积压恢复、人工位置降级和数据核对手册。示例全部脱敏。

## 6. 测试与验收

### 6.1 两层验收门槛

- 第一层“技术接入完成”：模拟器、自动化、性能、容量、安全和故障演练全部通过；
- 第二层“P6-2 完成”：4 台真实终端完成定位、苏标报警和附件控制验收。

第一层通过不得宣称真实终端已经接入或 P6-2 已完成。

### 6.2 协议正确性

使用经标准文档核对的固定十六进制报文和双向编解码测试覆盖：

- JT/T 808—2019 主版本和 2013 公共链路；
- 粘包、拆包、转义、校验、分包重组和超时清理；
- 注册、鉴权、心跳、位置和平台通用应答；
- 非法 BCD、超长报文、未知消息、错误版本和重复流水号；
- 苏标 ADAS/DMS 的 `0x0200` 扩展、开始/结束报警、一帧多报警和未知合法类型；
- 主动安全附件 `0x9208/0x1210/0x1211/0x1212/0x9212`；
- 1078 文件控制兼容 `0x9206/0x9207/0x1206`；
- 解码后重新编码得到协议等价报文。

固定样本至少覆盖前向碰撞、车道偏离、疲劳驾驶和接打电话四类报警，横跨 ADAS/DMS；这些样本必须来自标准文档或目标终端脱敏实报，不允许凭空构造字段布局。

### 6.3 安全与准入

自动化验证：

- 未预置、停用或绑定失效终端不能接入；
- 错误鉴权三次断开；新会话正确接管；
- 终端不能写其他车辆的位置或报警；
- 非法报文、连接洪泛和高频错误触发限流；
- 管理端和 SSE 权限矩阵、越权访问、并发处置冲突和附件访问控制；
- 媒体回调验签、防重放、文件类型/大小和文件名清洗；
- 日志、异常、指标、SSE 和管理接口不泄露鉴权码、完整报文、手机号、上传凭证和永久媒体地址；
- 依赖扫描不得存在未处置的严重漏洞，高危项必须修复或经书面接受。

### 6.4 位置质量

- WGS84 到 GCJ-02 相对核准基准点误差不超过 5 米；
- 覆盖正常、延迟、未来时间、乱序、零坐标、越界、跳点、超速、服务区外和定位无效；
- `GOOD/WARNING` 更新快照；`QUARANTINED` 保留历史但不污染快照；`REJECTED` 不生成事件；
- 重复投递只生成一条业务事件；
- GPS 离线后人工上报继续可用；
- 服务区外保持真实位置并告警。

### 6.5 主动安全报警

至少验证：

- 一条位置生成一条位置事件和多条报警，关联关系正确；
- 位置扩展损坏不影响基础位置，位置隔离不丢报警；
- 报警开始/结束、重复上报、乱序和未知类型处理正确；
- 报警状态机、乐观锁、操作审计和系统管理员受控重开正确；
- Outbox 与报警事务一致，API/发布器重启不丢失、不重复显示；
- SSE 新报警和状态变更 P95 在 API 入库后 2 秒内到达浏览器；
- SSE 重连可按 `Last-Event-ID` 补读，降级轮询最迟 5 秒显示；
- 无权限用户不能订阅或读取报警详情。

### 6.6 附件控制

- 在线且具备能力的终端可完成请求、上传信息、完成通知和平台应答；
- `0x1206` 只作为文件上传完成通知，不生成苏标报警；
- 媒体服务不可用时报警仍可用，附件进入 `WAITING_MEDIA_SERVICE`；
- 重复请求、回调和终端通知不生成重复附件；
- 上传超时、文件摘要不一致、超限文件和终端离线产生明确失败状态；
- 二进制流不经过网关和运营 API；
- 短时查看 URL 到期后失效，访问行为可审计。

### 6.7 性能

- 100 个并发 TCP 连接持续 1 小时；
- 每终端按 10 秒上报，位置不少于 36,000 条；
- 另执行 100 条/秒、持续 5 分钟的突发测试，并混入每秒 5 条报警和附件状态消息；
- 有效报文处理成功率不低于 99.9%；
- 本地缓冲成功后的终端应答 P95 ≤ 500 ms、P99 ≤ 2 s；
- 网关接收至运营 API 可查询 P95 ≤ 2 s、P99 ≤ 5 s；
- 正常网络下地图最迟 15 秒显示位置；报警 SSE P95 ≤ 2 s；
- 无事件循环阻塞、死锁、不明丢失或内存持续增长；
- 突发结束 10 分钟内队列和内存恢复稳定。

### 6.8 容量与查询

隔离数据库写入不少于 200 万位置事件、10 万报警、20 万报警动作/附件元数据，验证：

- 最新快照查询 P95 ≤ 500 ms；
- 单车单日位置历史 P95 ≤ 2 s；
- 质量筛选 P95 ≤ 2 s；
- 报警看板常用筛选 P95 ≤ 1 s；
- 报警详情含动作和附件元数据 P95 ≤ 1 s；
- 调度候选不扫描完整位置历史或报警表；
- 迁移前后人工位置数量、顺序和快照引用完全一致。

### 6.9 故障恢复

- 运营 API 中断 10 分钟：网关持久化，恢复后无丢失、无重复；
- 网关重启：缓冲补投，终端重新鉴权；
- 数据库短时不可用：API 明确失败，网关退避并保留数据；
- 网络半包、断连和重复登录正确释放会话；
- 缓冲高水位暂停读取并告警；缓冲写入失败不伪造成功；
- SSE 发布器重启后从 Outbox 恢复，客户端能补读；
- 媒体服务中断不影响位置和报警事实，恢复后可重试附件；
- 终端离线后人工位置和报警人工处置仍可工作。

### 6.10 真实终端验收

4 台终端分别完成：

- 白名单预置、注册、鉴权和车辆绑定；
- 执行中 10 秒、空闲 60 秒位置上报；
- 连续在线不少于 2 小时；
- 每车至少完成一段真实测试路线；
- 每车至少触发 1 个经安全条件控制的测试报警；全批至少覆盖 ADAS 和 DMS；
- 报警事实、地图位置、SSE 看板、处置动作和审计一致；
- 至少完成 1 个报警附件控制全链路，外部媒体服务可用时核验文件摘要；
- 拔电/断网、恢复、换绑、SSE 降级和人工位置降级各演练一次。

测试报警必须由终端厂商提供安全测试模式或静态回放生成，禁止在公共道路上通过危险驾驶动作触发。

### 6.11 验收证据

保留脱敏后的协议兼容矩阵、固定报文测试、注册鉴权和限流报告、位置质量样本、坐标误差、苏标报警矩阵、附件控制记录、SSE 恢复记录、100 连接性能报告、容量报告、故障演练、4 台真实终端路线/报警验收和敏感信息扫描结果。不得保存真实鉴权码、完整手机号、上传凭证或公开可访问的媒体地址。
