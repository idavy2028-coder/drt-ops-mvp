# 运营看板界面优化设计

## 1. 目标与范围

本阶段先落地管理后台“运营看板”，采用已确认的“通渭智慧公交”三段式信息结构：顶部核心指标、中部趋势图、下部分类统计。视觉上保留参考界面的高密度运营感，但统一使用当前网约公交系统的深色导航、白色数据面板和青绿色品牌色，避免照搬参考界面偏小字号、密集边框和弱层级的问题。

本阶段必须完成：

1. 顶部优先展示当日订单量、任务完成率、平均等待时间、车辆利用率四个核心指标。
2. 指标卡同时显示绝对值与比例或相对变化，并显示“正常 / 偏高 / 偏低”状态和对比基线。
3. 中部展示截至当前运营日的近 7 天趋势，默认组合展示订单量和任务完成率，并允许切换平均等待时间、车辆利用率。
4. 趋势图标题、日期范围、横坐标、图例、单位和纵轴必须随当前指标同步变化。
5. 下部展示订单状态、任务状态和车辆状态分类统计；每个分类同时显示数量和百分比。
6. 使用真实聚合接口，不在前端构造或保留示例数据。

本设计不包含其余管理页面的具体实现；订单中心、车辆任务、位置历史、资源与规则配置、审计日志、用户与权限以及全局导航缓存将在后续设计与实施任务中继续完成，并最终合并到同一界面优化分支。

## 2. 已确认的视觉方向

- 整体风格：高密度、克制、面向运营人员的实用型工作台。
- 导航：深蓝黑背景，当前菜单使用青绿色高亮；后续接入“基础数据”树状分组。
- 内容区：浅灰蓝画布、白色面板、细边框、弱阴影，减少无效留白。
- 品牌强调：青绿色用于主要数据和当前状态，蓝色用于执行与比例趋势，橙色用于偏高提示，红色仅用于真实异常。
- 间距：页面与组件采用 12px 基础间距；卡片内边距 16px；图表面板内边距 12px 至 16px。
- 字号：指标值 28px 至 32px，面板标题 16px，正文 13px 至 14px，辅助信息不低于 12px。

## 4. 核心指标定义

### 4.1 当日订单量

- 主值：所选运营日订单总数，显示为 `128 单`。
- 辅助比例：相对基线变化率，显示为 `较基线 +9.4%`。
- 基线：所选运营日前 7 个完整运营日的日均订单量。
- 状态：相对基线变化绝对值不超过 10% 为“正常”；高于 10% 为“偏高”；低于 -10% 为“偏低”。

### 4.2 任务完成率

- 主值：`已完成任务数 / 当日任务总数`，例如 `110/119`。
- 比例：同卡显示 `92.4%`。
- 基线：前 7 个完整运营日的合计完成数除以合计任务数，避免简单平均每日百分比造成权重偏差。
- 状态：与基线差值在正负 3 个百分点以内为“正常”，高于 3 个百分点为“偏高”，低于 -3 个百分点为“偏低”。
- 当分母为零时显示 `0/0 · --`，状态为“暂无当日数据”，不把无任务误报为 0% 完成率或“暂无基线”。

### 4.3 平均等待时间

- 主值：有等待时间估计的调度决策平均值，例如 `8.6 分钟`。
- 绝对量补充：显示有效样本数，例如 `样本 121 单`。
- 辅助比例：相对基线变化率，例如 `较基线 -14.0%`。
- 基线：前 7 个完整运营日全部有效样本的加权平均等待时间。
- 状态：相对基线变化绝对值不超过 10% 为“正常”；高于 10% 为“偏高”；低于 -10% 为“偏低”。
- 当无有效样本时显示 `-- 分钟 · 样本 0 单`，状态为“暂无当日数据”。

### 4.4 车辆利用率

- 主值：`当日参与有效任务的车辆数 / 当前可调度车辆总数`，例如 `19/25`。
- 比例：同卡显示 `76.0%`。
- 有效任务排除 `CANCELLED` 和 `EXCEPTION`。
- 当前可调度车辆为 `dispatchable=true` 的车辆。由于现有车辆表没有历史启停快照，近 7 天均使用当前可调度车辆数作为分母，界面帮助文案明确显示“按当前可调度车辆口径”。
- 基线：前 7 个完整运营日利用率的平均值。
- 状态：与基线差值在正负 5 个百分点以内为“正常”，高于 5 个百分点为“偏高”，低于 -5 个百分点为“偏低”。
- 当可调度车辆数为零时显示 `0/0 · --`，状态为“暂无当日数据”。

“偏高 / 偏低”只描述相对基线方向，不直接等同于好坏。红色不用于普通偏差，只用于系统错误或业务异常。

所有状态判断使用未格式化的高精度内部值，API 只在输出时统一格式化。若当日指标没有有效分母或样本，指标卡优先显示中性标签“暂无当日数据”，API 状态返回 `NO_DATA`；当日指标有效但前 7 个完整运营日无法形成有效基线时，显示“暂无基线”，API 状态返回 `NO_BASELINE`。不得用“正常”掩盖数据不足。订单量基线为零时，当前也为零则显示“正常”，当前大于零则显示“偏高”，变化率显示 `--`。

## 5. 近 7 天趋势图

### 5.1 日期与标题一致性

- 本阶段页面以 `Asia/Shanghai` 当前运营日为结束日期，包含结束日期在内向前取 7 天；聚合 API 保留 `endDate` 参数，供后续历史运营日选择复用。
- 默认标题为 `近 7 天订单量与任务完成率趋势（08-07 至 08-13）`。
- 横坐标固定输出 7 个按日期升序排列的 `MM-DD` 标签；没有数据的日期也必须返回并显示为零值或无样本值。
- 默认组合图左轴标题为 `订单量（单）`，右轴标题为 `任务完成率（%）`。
- 切换“平均等待”后，标题改为 `近 7 天平均等待时间趋势（08-07 至 08-13）`，纵轴单位改为 `分钟`，隐藏无关图例和右轴。
- 切换“车辆利用率”后，标题改为 `近 7 天车辆利用率趋势（08-07 至 08-13）`，纵轴单位改为 `%`，隐藏无关图例和右轴。
- 页面跨日后刷新时，标题、7 个数据点和横坐标同时更新，不允许沿用旧日期标签。

### 5.2 图表交互与可访问性

- 默认使用订单量柱形图和任务完成率折线图，避免两个不同量纲共用同一纵轴。
- 鼠标悬停或键盘聚焦数据点时显示完整日期、绝对值、分子/分母和比例。
- 图表下方提供屏幕阅读器可读的数据摘要；颜色不是区分系列的唯一方式，折线同时使用点标记。
- 窄屏下保留横向 7 个日期，不隐藏日期点；必要时允许图表区域水平滚动。
- 图表采用项目内 Vue + SVG 组件实现，不新增图表运行时依赖，以控制包体、审计面和主题一致性。

## 6. 分类统计与百分比

### 6.1 订单状态分布

- 待处理：`PENDING_DISPATCH`、`PENDING_MANUAL_REVIEW`。
- 执行中：`CONFIRMED`、`IN_PROGRESS`。
- 已完成：`COMPLETED`。
- 异常/取消：`UNSERVICEABLE`、`CANCELLED`、`EXCEPTION_CLOSED`。

### 6.2 任务状态分布

- 待发车：`PENDING_DEPARTURE`、`DISPATCHED`。
- 执行中：`IN_PROGRESS`、`PAUSED`。
- 已完成：`COMPLETED`。
- 异常/取消：`EXCEPTION`、`CANCELLED`。

### 6.3 车辆状态分布

- 执行中：`IN_SERVICE`、`DISPATCHED`。
- 空闲：`IDLE` 且 `dispatchable=true`。
- 异常/不可用：其余状态或 `dispatchable=false`。

每个图例项显示 `名称 · 数量 · 百分比`，例如 `已完成 83 单 · 64.8%`。百分比按一位小数展示；为避免独立四舍五入后合计为 99.9% 或 100.1%，先向下取十分位整数，再按原始小数余数从大到小分配剩余份额，使所有分类非负且合计严格为 `100.0%`。无数据时不绘制空环，改为友好空状态 `当日暂无可统计数据`。

## 7. 数据接口设计

### 7.1 方案比较

1. 单一看板聚合接口：一次返回核心指标、基线、近 7 天趋势和分类统计。优点是统计口径一致、请求少、刷新得到同一数据快照；缺点是 DTO 较大。
2. 前端并发调用 7 次现有单日汇总接口，再拉取订单、任务和车辆列表自行聚合。改动较少，但请求多、权限与口径分散，页面可能出现不同步数据。
3. 将核心指标、趋势和分类拆成三个接口。模块边界清楚，但首屏需要协调多次请求和多个加载状态。

采用方案 1。运营看板是一个整体读模型，单一聚合接口最能保证标题、日期、指标和图表口径一致。

### 7.2 新接口

`GET /api/metrics/operations-dashboard?endDate=2026-08-13&days=7`

- `endDate` 为空时使用 `Asia/Shanghai` 当前运营日。
- `days` 当前仅允许 `7`，保留参数是为了明确契约并方便后续扩展；非法值返回 400。
- 保留现有 `/api/metrics/operations-summary`，避免破坏既有调用和测试。
- 响应包含：`operatingDate`、`rangeStart`、`rangeEnd`、四个核心指标、7 个趋势点、三组分类统计和 `generatedAt`。
- 所有比率在 API 中使用 0 至 1 的十进制值，前端统一格式化为百分比；计数使用整数，分钟保留两位小数。
- 无分母的比率返回 `null`，不返回具有误导性的零；无有效基线时基线字段和变化字段也返回 `null`，状态返回 `NO_BASELINE`。
- 当日无有效分母或样本时状态返回 `NO_DATA`；该状态优先于 `NO_BASELINE`，用于区分“今天没有可判断的数据”和“今天有数据但历史基线不足”。

### 7.3 首版性能边界

首版按实施计划一次读取订单、调度决策、车辆任务和车辆后在内存中完成 7 日聚合，适用于当前试点数据规模。该实现不代表生产规模化方案；随着历史数据增长，必须改为按上海运营日范围查询并由数据库聚合，避免 `findAll()` 导致请求耗时和内存占用随全量历史线性增长。上线容量评审前应增加数据量基准测试并设定切换阈值。

## 8. 前端组件边界

- `DashboardPage.vue`：负责运营日、刷新、加载状态和页面编排，不直接实现图表几何计算。
- `DashboardMetricCard.vue`：展示主值、绝对量/比例、状态、基线和变化。
- `OperationsTrendChart.vue`：根据选中的趋势模式计算标题、图例、坐标轴和 SVG 图形。
- `DistributionDonut.vue`：绘制单组环图，并输出数量和百分比图例。
- `dashboardMetrics.ts`：集中处理百分比、百分点、分钟、日期范围和无数据格式。
- `operationsStore.ts`：从只保存单日汇总扩展为保存看板聚合数据；刷新期间保留上一次成功数据并显示局部加载状态，避免整页闪烁。

组件只接收已经定义的展示模型，统计口径由后端决定；前端不得通过重新分类原始订单列表来生成另一套口径。

## 9. 加载、错误与空状态

- 初次加载：四张指标卡和图表区域显示骨架屏。
- 手动刷新：保留旧数据，在刷新按钮和更新时间旁显示同步状态。
- 成功刷新：使用全局 Toast 提示 `运营数据已更新`。
- 请求失败且存在旧数据：继续显示旧数据，Toast 提示失败，并标明 `数据更新时间`。
- 请求失败且无旧数据：显示可重试空状态，不渲染为全零数据。
- 单个日期无数据：趋势点按计数零、无分母比率 `null` 处理，折线在该点断开；悬浮信息显示 `无有效样本`。

## 10. 响应式与可访问性

- 1440px 及以上：四列指标卡、单行三张分类图。
- 900px 至 1439px：指标卡两列；分类图两列或单列；主趋势图保持完整宽度。
- 900px 以下：左侧导航按全局方案折叠；指标卡单列；图表最小绘图区 720px 并允许容器水平滚动。
- 状态标签和图表系列均提供文字说明；键盘可聚焦趋势点和指标切换按钮。
- 图表 SVG 提供 `role="img"` 和动态 `aria-label`，同时输出不可见数据表供辅助技术读取。

## 11. 验证范围

### 后端

- 上海时区跨 UTC 日期边界的 7 日范围。
- 7 个日期完整、升序且无数据日补齐。
- 四个指标的分子、分母、比例、基线和状态边界。
- 零订单、零任务、零可调度车辆和无等待样本。
- 三组分类数量守恒，分类合计等于对应总数。
- `days` 非法参数返回 400，权限继续要求 `METRICS_READ`。

### 前端

- 四张指标卡显示绝对值与比例/变化。
- 默认趋势标题、左右轴、图例和 7 个横坐标一致。
- 两个趋势切换模式同步更新标题、单位与图例。
- 分类图例显示数量和百分比，展示百分比合计 100.0%。
- 加载骨架、无数据、刷新失败保留旧数据和全局 Toast。
- 1440×900 首屏布局与窄屏回归。

## 12. 实施顺序

1. 先用测试锁定后端聚合口径和新接口契约。
2. 实现看板 API 和前端类型、数据存储。
3. 用组件测试驱动指标卡、趋势图和分类图。
4. 重构运营看板页面并接入全局 Toast、骨架屏和响应式样式。
5. 运行后端、前端、类型检查和构建验证，再进行浏览器视觉复验。
