# 调度工作台地图可用性修复设计

## 1. 目标与范围

本轮采用已确认的 A+C 混合方案：以“地图主导 + 车辆侧栏”为整体框架，并融入“全景指挥地图”的轻量浮层信息。目标是让调度员在一个可视高度内完成车辆定位、图层开关、任务识别和待处理事项浏览。

本轮包含：

- 地图容器与 Leaflet 画布始终同高，消除底部灰色空白。
- 服务区、虚拟站点、任务线和车辆标记统一通过同一 GCJ-02 → WGS84 转换进入 Leaflet 图层。
- 缩放、拖动和 15 秒车辆位置刷新时保留调度员当前视野，不重复自动缩放。
- 车辆使用真实经纬度地图标记；标记按状态着色，点击显示轻量浮层。
- 左侧为精简待处理订单/任务列表，中央为主地图，右侧为车辆列表；地图标记与车辆列表双向联动。
- 图层控制仅保留“服务区边界”“虚拟站点”“车辆标记”，任务路线随所选任务展示，不作为本轮新增开关。

本轮不包含：

- 不修改车辆位置采集、数据库、API 返回结构或 15 秒轮询口径。
- 不把人工上报离散节点描述为真实 GPS 轨迹。
- 不新增地图供应商或引入新的地图依赖。
- 不启动 P6-2，不修改 P6-1 评估证据。

## 2. 已确认根因

### 2.1 地图底部空白

`DispatchWorkbenchPage.vue` 的三列网格使用 `align-items: stretch`。左侧实时订单数量较多时，整行高度被列表撑大；`DispatchMap.vue` 只设置 `min-height: 430px`，Leaflet 在初始尺寸建立画布后没有收到容器尺寸变化通知，因此父容器继续增高而瓦片画布保持旧尺寸，形成底部空白。

修复原则：调度控制台使用明确的可视高度，左右侧栏内部滚动；地图根节点和画布均为 `height: 100%`。使用 `ResizeObserver` 监听地图容器，在尺寸变化后调用 Leaflet `invalidateSize({ pan: false })`。

### 2.2 图层移动后看似偏移或不同步

服务区和虚拟站点本身已通过 `toLeafletLatLng` 转为 Leaflet 坐标，但当前每次位置轮询、任务变化或图层开关都会清空全部图层并执行 `fitLayers`。这会覆盖调度员刚完成的缩放或拖动操作。与此同时，车辆详情卡使用 `left/top` 百分比绝对定位，不属于 Leaflet 图层，地图移动时不会跟随，进一步造成“地图内容不同步”的视觉判断。

修复原则：所有具有地理位置的对象都必须成为 Leaflet 图层；只在首次加载或用户点击“回到全局”时执行全图适配。普通数据刷新只更新图层，不重置视野。

### 2.3 车辆位置不准确且信息噪声大

当前同时创建真实经纬度 Leaflet marker 和按索引分配百分比位置的 DOM 车辆卡片。DOM 卡片的位置与车辆坐标无关，并直接显示完整任务 UUID，多个卡片还会互相遮挡。

修复原则：删除地图上的绝对定位车辆卡片。车辆只保留一个真实坐标 marker；信息通过 marker popup 和右侧车辆栏展示。任务号统一显示前 8 位，完整 UUID 仅保留在内部选择状态和 API 调用中。

## 3. 界面与交互设计

### 3.1 三栏地图控制台

- 左栏宽度约 260px：显示待调度、待复核和活动任务的精简列表；列表自身滚动。
- 中栏占据剩余宽度：地图高度为调度控制台高度的 100%，最小高度 560px。
- 右栏宽度约 300px：显示所有车辆的车牌、状态、最后反馈时间和短任务号；列表自身滚动。
- 视口小于 1180px 时，右侧车辆栏改为地图下方横向/双列列表；视口小于 820px 时切换为单列页面，不制造横向滚动。

### 3.2 车辆标记和浮层

车辆标记使用 Leaflet `divIcon`：

- 空闲：绿色。
- 已派单/执行中：蓝色。
- 离线、异常或服务区外：红色。
- 无法识别的其他状态：灰色。

点击标记后：

- 打开 Leaflet popup，展示车牌、中文状态、短任务号、最后反馈时间。
- 向父页面发出车辆选择事件，右侧列表同步高亮。

点击右侧车辆列表项后：

- 父页面更新 `selectedVehicleId`。
- 地图调用 `focusPoint` 聚焦到真实车辆坐标并打开对应 popup。
- 不改变当前图层开关，不重新适配全部边界。

### 3.3 地图浮层与图层控制

- 左上角：三个紧凑开关——服务区边界、虚拟站点、车辆标记。
- 右上角：显示底图错误或位置较久未更新提示。
- 右下角：提供“回到全局”按钮，只有该按钮和首次加载会执行 `fitBounds`。
- 所选任务的路线和人工节点链保留；人工节点继续明确标注为“离散节点，不是实际轨迹”。

## 4. 组件边界与数据流

### `DispatchWorkbenchPage.vue`

负责加载订单、任务、人工复核、服务区、站点和车辆位置；新增 `selectedVehicleId`，协调左栏、地图和右栏，不直接操作 Leaflet。

### `DispatchMap.vue`

负责 Leaflet 生命周期、地图尺寸同步、地理图层和 popup。新增 `selectedVehicleId` 属性和 `selectVehicle` 事件；不再渲染非地理定位车辆卡片。

### `VehicleLocationSidebar.vue`

新增纯展示组件。输入车辆快照和当前选中车辆 ID，输出 `select` 事件。组件只显示短任务号，不保存业务状态。

### `tileMapRuntime.ts` / `tileMapTypes.ts`

为地图运行时增加两个窄接口：

- `invalidateSize()`：父容器变化时同步 Leaflet 画布。
- `focusPoint(point, zoom)`：从 GCJ-02 坐标聚焦车辆，不把坐标转换逻辑泄露给页面组件。

数据流：API 快照 → `DispatchWorkbenchPage` → 地图 marker 与车辆侧栏；侧栏选择 → 页面选中状态 → 地图聚焦；地图 marker 点击 → 页面选中状态 → 侧栏高亮。

## 5. 错误处理与安全边界

- 经纬度不是有限数字的车辆不创建 marker，并在右侧栏标记“位置不可用”。
- 底图失败时保留现有静态摘要和车辆侧栏，避免把底图故障误报为登录失效。
- `ResizeObserver` 不可用时仍保持 CSS 100% 高度；不影响基本地图初始化。
- popup 和侧栏只使用 Vue/Leaflet DOM API 构造文本节点或受控 HTML，不拼接乘客信息。
- 不显示乘客姓名、电话、完整任务 UUID或密钥。

## 6. 验收标准

1. 在 1366×768 和 1920×1080 视口下，地图容器与 Leaflet 画布底边一致，无灰色空白。
2. 拖动、缩放地图后，服务区、站点和车辆保持相对位置一致；15 秒位置刷新不重置视野。
3. 服务区、站点、车辆均通过同一坐标转换函数进入 Leaflet。
4. 车辆 marker 的坐标等于对应快照的转换结果，状态颜色符合规则。
5. marker popup 只显示车牌、状态、短任务号和最后反馈时间。
6. 点击车辆侧栏后地图聚焦并打开该车辆 popup；点击 marker 后侧栏高亮。
7. 三个图层开关可独立隐藏或显示目标图层。
8. 管理端类型检查、全量 Vitest 和调度工作台 Playwright 用例通过。
